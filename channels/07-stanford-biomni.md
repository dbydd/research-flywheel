# 07 - Stanford Biomni：通用生物医学智能体

| 字段 | 内容 |
|------|------|
| **机构** | Stanford SNAP Lab，Jure Leskovec / Kexin Huang 团队；关联 HAI |
| **论文/发布时间** | bioRxiv 2025.05.30.656746（2025-05-30 预印），Biomni: A General-Purpose Biomedical AI Agent；官网 biomni.stanford.edu；GitHub snap-stanford/Biomni |
| **用途** | 通用生物医学任务自动化：因果基因优先级、药物重定位、罕见病诊断、微生物组分析、分子建模、单细胞注释、GWAS 解析等数十类任务，支持研究人员用自然语言一键编排复杂工作流 |
| **验证状态** | 纯计算基准验证 + 8 个真实场景任务验证，无自带湿实验室，依赖外部实验复核；已建立 Biomni-Eval1 基准（433 实例，10 任务） |

## 循环形态

Biomni 采用单智能体规划-检索-执行-自检循环，循环封装在 Biomni-A1 中：

1. **规划**：LLM Planner 将用户自然语言目标分解为可执行代码计划，计划以 Python 代码形式表达，包含工具调用序列与数据流。
2. **检索增强**：检索模块在规划前与规划中查询 59 个数据库与文献库，补充最新生物医学知识，缓解幻觉。
3. **执行**：沙盒环境按计划顺序调用 150 个工具与 105 个软件包，执行计算、查询、统计与可视化。
4. **自检与重试**：执行结果回传给 LLM，评估是否满足目标，失败时自动修正计划并重试，循环持续至任务完成或达到步数上限。
5. **社区扩展循环**：E1 为官方发布环境，E2 为社区驱动扩展环境，新增工具与数据集通过统一 schema 注册，形成持续生长的生态。

该循环强调整体自动化，单次任务无需预定义模板，适合异构生物医学问题。

## 智能体架构

| 组件 | 功能 |
|------|------|
| Biomni-A1（Agent） | 核心推理与规划引擎，基于 LLM，生成代码级行动计划 |
| Biomni-E1/E2（Environment） | 工具、数据库、软件包的统一执行环境，提供沙盒与依赖隔离 |
| 检索增强模块 | 对接文献与结构化数据库，提供上下文 grounding |
| 代码执行层 | 在沙盒中运行生成的 Python/R 代码，捕获输出与错误 |
| Biomni-Eval1 | 10 任务 433 实例的评估基准，用于回归测试与生态贡献验证 |

架构设计避免硬编码工作流，Planner 通过工具注册表动态发现可用能力，具备跨任务泛化能力。

## 工具/数据库/软件

- **工具 150 个**：覆盖序列处理、变体注释、富集分析、通路查询、药物-靶点预测、文献检索等。
- **数据库 59 个**：基因组变体、蛋白结构、通路、疾病关联、药物相互作用、文献等；示例包括 dbSNP、UniProt、Reactome、DisGeNET、PubMed。
- **软件包 105 个**：生物信息学、分子建模、单细胞、统计与可视化栈；示例包括 scanpy、Biopython、RDKit、GSEA、Seurat。
- **代码执行**：支持 Python 与 R 生态，自动安装依赖并管理版本。
- **数据接入**：支持用户自带私有数据集与私有知识库注入。

## 度量

- **HLE（Humanity's Last Exam）**：Biomni 17.3% 准确率，基座 LLM 6.0%，提升 402.3%；超越 coding agent 43.0%，超越 Biomni-ReAct 消融 20.4%。
- **LAB-Bench DbQA**：74.4% 接近人类专家 74.7%，远超 coding agent 40.8%。
- **LAB-Bench SeqQA**：81.9% 超过人类 78.8%。
- **真实场景 8 任务**：因果基因排序、罕见病诊断等均显著优于基线，具体任务分数见论文表 2。
- **系统度量**：工具调用成功率、检索命中率、代码执行通过率。

## 闭环验证（湿实验/临床）

Biomni 闭环停留在计算验证层，未内置湿实验或临床闭环。验证方式为基准问答与真实科研任务回放，评估指标为准确率与专家打分。潜在湿实验验证依赖用户自行对接实验室，Biomni 输出包含实验方案与候选清单，适合作为干实验到湿实验的桥梁。

## 开源状态

完全开源。GitHub snap-stanford/Biomni 含 Agent、Environment、Benchmark、示例脚本；E1 环境可一键安装；E2 接受社区贡献；论文与细节文档开放；2025 年 9 月团队将 Biomni 商业化分拆，社区版保持开源。

## 核心可借鉴点

1. **工具注册表驱动**：150 工具通过统一 schema 注册，Planner 动态发现，新增能力无需改 Agent 核心。
2. **代码即计划**：用可执行代码表达计划，执行与验证一体化，便于日志回放与错误定位。
3. **检索与执行解耦**：检索模块独立于规划，避免 LLM 记忆过时，支撑长尾生物医学知识。
4. **Benchmark 即生态**：Biomni-Eval1 433 实例为社区提供统一度量，贡献者可见直接收益。
5. **E1/E2 双轨**：官方稳定环境与社区实验环境分离，兼顾可靠性与扩展性。

## 潜在坑

1. 工具爆炸带来选择困难，Planner 在长工具列表上召回率下降，需要 ToolRAG 类检索。
2. 沙盒依赖复杂，105 软件包版本冲突常见，环境复现成本高。
3. 序列与数据库问答准确率高，开放式假设生成能力仍弱于专用假设生成系统。
4. 无湿实验闭环，输出结果需要外部专家二次校验，直接用于临床存在风险。
5. 社区 E2 质量参差，需要审核机制避免低质工具污染注册表。

## 落到 OMP Workspace 的可实现机制

| 借鉴点 | OMP 实现 |
|--------|----------|
| 工具注册表 | `template/biomni-registry.json` 定义 tool schema，`channels/07-*` 执行时通过 `read` 动态加载，新增工具仅追加注册项 |
| 代码即计划 | 约束子智能体输出 `plan.py` 与 `run.sh` 双产物，`hub` 协调执行，日志落 `artifact://biomni-run/{task_id}` |
| 检索增强 | 独立 `retriever` 子智能体对接 PubMed 与本地 `vault://` 知识库，产出 `context.md` 供 Planner 引用 |
| 双轨环境 | `template/env-e1/` 锁定依赖版本，`template/env-e2/` 允许社区扩展，CI 仅对 E1 强校验 |
| 基准驱动 | 复用 Biomni-Eval1 思路，在 `research-flywheel/eval/` 建立 10 任务回归集，每次新增 channel 自动跑分 |

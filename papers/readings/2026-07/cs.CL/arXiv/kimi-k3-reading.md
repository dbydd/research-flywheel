# Kimi K3: Open Frontier Intelligence 精读

- 本体：`raw/2026-07/cs.CL/arXiv/kimi-k3/`
- 摘要：[[kimi-k3-abstract|Kimi K3 摘要]]
- 内部视角：[[k3-moe-attention-abstract|简单谈谈K3的MoE和Attention]]（作者为 Kimi 研究员苏剑林，逐条交代 MoE 与 Attention 的取舍）

## 问题与做法

**要解的问题：开源模型在预训练规模这条轴上的位置。** 本页精读 Kimi Team（月之暗面）集体署名的技术报告《Kimi K3: Open Frontier Intelligence》（arXiv 编号 2607.24653v2，首次提交于 2026 年 7 月 27 日，主分类 cs.CL，正文八节加六个附录）。报告开篇把大模型的算力投入分成两条轴：一条是部署前的预训练，用更大的模型配更多的数据换更强的基座；另一条是测试时算力，用强化学习、更长的思考与更多的工具调用换推理能力。报告的判断是，开源生态在第二条轴上进展很快，许多近期模型的总参数停在 1T 级或略高，同一时期闭源前沿在第一条轴上继续把基座做大，两边的预训练规模差距没有收窄；在规模相近的预训练基座上叠加越来越复杂的推理与智能体强化学习，测试时算力补不平基座规模上的差，开源与最强闭源之间的差距会重新拉开。Kimi K3 同时推两条轴：把预训练基座做到 3T 级参数，把强化学习、推理力度与长程交互扩到 100 万 token 的上下文。

K3 是多模态稀疏混合专家模型（Mixture-of-Experts，MoE：把前馈层拆成许多并行的小网络即专家，前馈层指注意力层之后那条逐位置的全连接子层；每个 token 只走其中几个，token 是模型处理文本的最小单位，一个词或词的一部分算一个；总参数随专家总数增长，计算量随实际激活的专家数增长）。总参数 2.78 万亿，每 token 激活 1042 亿，原生支持图像与视频，上下文窗口最长 104.8 万 token。报告的架构主线是把信息流沿三个方向同时扩展：序列方向、网络深度方向、模型宽度方向。

**序列轴之一：KDA 的状态更新。** KDA（Kimi Delta Attention，Kimi 增量注意力）把 delta 规则（一种让记忆状态按预测误差写入的线性注意力规则）扩展出一个逐通道遗忘门。KDA 的代价账是每个位置只保留一个固定大小的循环状态，长序列的混合成本不随长度增长。注意力机制里，每个位置有一组查询向量、键向量与值向量：查询是当前位置发出的提问，键是各历史位置的索引，值是各历史位置携带的内容；注意力输出用查询与各键的相似度给各值加权求和，权重归一化到总和为一。设第 t 个位置的输入表示为向量 $\boldsymbol{x}_t$，模型隐维为 d；先看单个注意力头，它有查询向量 $\boldsymbol{q}_t$、键向量 $\boldsymbol{k}_t$（都在 $\mathbb{R}^{d_k}$）、值向量 $\boldsymbol{v}_t\in\mathbb{R}^{d_v}$ 与循环状态 $\boldsymbol{S}_t\in\mathbb{R}^{d_k\times d_v}$。状态按

$$
\boldsymbol{S}_t=\left(\boldsymbol{I}-\beta_t\boldsymbol{k}_t\boldsymbol{k}_t^{\top}\right)\operatorname{Diag}(\boldsymbol{\alpha}_t)\boldsymbol{S}_{t-1}+\beta_t\boldsymbol{k}_t\boldsymbol{v}_t^{\top},\qquad\tilde{\boldsymbol{o}}_t=\boldsymbol{S}_t^{\top}\boldsymbol{q}_t
$$

更新，输出由状态与查询的内积给出。这里 $\boldsymbol{\alpha}_t\in(0,1)^{d_k}$ 是每通道的一步保留因子，$\beta_t\in(0,1)$ 是写入强度：$\operatorname{Diag}(\boldsymbol{\alpha}_t)$ 先把历史状态按通道衰减，衰减后的状态乘上当前键就是它对当前值的预测，$\boldsymbol{I}-\beta_t\boldsymbol{k}_t\boldsymbol{k}_t^{\top}$ 再按当前键方向减掉这份预测，后面的写入项补上真实值。参数化沿用前作 Kimi Linear（arXiv 2510.26692）：查询与键经线性投影、短卷积（对相邻若干位置做一维卷积，混合局部上下文）、Swish 激活与 L2 归一化；值走短卷积与 Swish；写强度由 Sigmoid 给出；衰减用一个低秩投影加每头偏置产生的衰减对数 $\boldsymbol{z}_t$ 表示。

训练与前填充按分块形式并行：块内并行，块间串行。块大小记 C，通道累积衰减 $\boldsymbol{\gamma}$ 是块内保留因子的连乘；一个变换（前作称为 UT 变换）把值矩阵折成伪值项，块输出写成两项之和，一项是块间状态通过累积衰减带进来的信息，另一项是块内类似注意力的交互。

**下界衰减。** 分块形式要用累积衰减的倒数 $1/\boldsymbol{\Gamma}$ 去缩放键。累积衰减是若干个小于 1 的因子连乘，它的倒数可以任意大，在有限精度里会溢出。前作用对数空间计算相对衰减，并把每个块切成 16 token 的小块：对角块之外的小块因此能直接走稠密矩阵乘，对角块上仍要逐位置对（position-pair）计算，成为块内的主要瓶颈。K3 改的是衰减对数到每步对衰减的映射：前作用负 Softplus，$g=-e^{A}\operatorname{Softplus}(z)$，取值落在整个负半轴；K3 改用带缩放的 Sigmoid，

$$
\boldsymbol{g}_t=g_{\min}\operatorname{Sigmoid}\!\left(e^{A_h}\boldsymbol{z}_t\right)\in(g_{\min},0)^{d_k},\qquad \boldsymbol{\alpha}_t=\exp(\boldsymbol{g}_t)\in\left(e^{g_{\min}},1\right)^{d_k},
$$

其中 $A_h$ 是每头可学的对数尺度，下界固定为 $g_{\min}=-5$。于是每个保留因子都大于 $e^{-5}\approx 6.7\times10^{-3}$，16 token 一小块的累积对衰减落在 $(-80,0)$ 区间，对应的倒数缩放因子小于 $e^{80}$，留在 BF16（十六位浮点格式，指数范围比 32 位浮点窄）的动态范围之内。数值范围有界之后，对角块与对角外块都用稠密 Tensor Core 矩阵乘，逐位置对的计算路径被整体去掉。报告说这条参数化与先行工作里的下界循环门控关系密切，并点名 HGRN2、Griffin 与 RWKV-7 三件。

**满秩输出门。** KDA 的输出门从低秩参数化换成输入相关的满秩投影：先对循环输出做逐头 RMSNorm（用均方根归一化的归一化层），再按 y = 投影( Sigmoid(另一条投影 x) ⊙ 归一化后的输出 ) 施加数据相关门控。Gated MLA 一侧也用了同一种满秩门。

**序列轴之二：Gated MLA 与 NoPE。** MLA（Multi-head Latent Attention，多头潜在注意力）出自 DeepSeek-V2：它把每个 token 的键值表示压成一个低维潜变量 $\boldsymbol{c}_t$，缓存 $\boldsymbol{c}_t$ 并在注意力计算时用学到的上投影重建内容键与内容值，KV 缓存（键值缓存，生成时避免重算历史注意力而存下的中间量）因此变小，全局的 token 到 token 注意力保留下来。K3 在定期的全局注意力层沿用 MLA，并加上输入相关、逐通道的满秩输出门。报告另有一处精度决定：低精度 Flash Attention 的带偏舍入误差已有分析工作指出，K3 因此在训练时把注意力输出留在 FP32（32 位浮点），输出块的片上占用翻倍，训练内核改成让它与 KV 暂存缓冲重叠，把共享内存让给更深的 KV 流水线。

K3 的 MLA 层全部走 NoPE（No Position Encoding，不加显式位置编码）：查询与键上不加任何位置编码，位置敏感与近因感知的序列混合由中间的 KDA 层提供，MLA 层提供不受位置限制的全局内容交互。报告说这条分工还省掉了扩上下文时改位置编码参数的动作，例如重调旋转位置编码的频率基或施加 YaRN 一类外推。

博客作者（Kimi 研究员苏剑林）对这一段给出了机制层的补充。K3 可以把旋转位置编码加回去，加上之后效果看不出变化，按最简洁的原则就不加了；一个全 MLA 的模型（例如 K2）去掉旋转位置编码会明显变差，K3 能用 NoPE 靠的是 KDA 与 MLA 的混合结构。理由是一项等价推导：任意正交矩阵的幂都能用来构建广义的旋转位置编码，常见做法选简单的旋转矩阵，PaTH 一类工作选 Householder 矩阵；在正交情形下，PaTH 可以等价地写成对查询与键各减去一个 DeltaNet 项之后的软最大化注意力（softmax，把一片分数变成一组总和为一的权重），也就是给查询与键加上 DeltaNet 就能起到类似位置编码的作用。KDA 属于更一般的 DeltaNet，所以「KDA 与 MLA 混合」的模型自带一种广义旋转位置编码。MLA 仍保留拼接 64 维的做法，理由是适配既有的 MLA 基础设施并控制计算量；直接投影出 576 维潜变量再分出键与值的做法更简洁，代价是计算增加而效果收益很小，K3 已经引入 KDA 与注意力残差等新变量，MLA 上就不再动结构。他把保留 MLA 的理由归结为四条约束：效果不低于 MLA，训练与前填充成本不超过 MLA，KV 缓存比 MLA 小，解码算力比 MLA 小；他给出当前没有简单优雅的注意力设计能同时满足这四条的判断。往小了改（128+128 的 GQA8，加号两侧分别指查询-键头维与值头维，各 128；GQA8 是分组查询注意力，每 8 个查询头共享一组键值头）在效果上很难打赢 MLA，KV 缓存还是 MLA 的三倍多；往大了改（256+256 的 MFA，查询-键头维与值头维各 256；MFA 是 Multi-matrix Factorization Attention，本质上是一个所有查询头共享一组键值的 MQA）效果能追回、缓存也不多，代价落在训练与预填充成本上。多 token 预测与投机解码让 MLA 的解码形式（把所有查询头共享同一组键值、头维 512 以上的 MQA，即多查询注意力）提前消耗算力，这一条是他判断「MLA 加多 token 预测容易吃亏」的理由。

**深度轴：Attention Residuals。** 常规残差连接把之前所有层的信息压进一个状态，报告说这在深度方向上像一个随时间递归的循环网络，构成瓶颈。注意力残差（AttnRes）把注意力机制搬到深度上：每层有一个可学的伪查询 $\boldsymbol{w}_l$，键与值取嵌入与各前序层的输出，注意力权重用软最大化核 $\phi(\boldsymbol{q},\boldsymbol{k})=\exp(\boldsymbol{q}^{\top}\operatorname{RMSNorm}(\boldsymbol{k}))$ 计算，本层输出是这些表示的加权和；核里套 RMSNorm 是为了让输出幅度大的层不会独自支配权重。整版形式的算术量是层数的平方乘隐维，层数不到一百时开销可接受，实际代价是 $O(Ld)$ 的显存与流水线并行（把不同层段放到不同设备上、按流水线喂微批）下的跨级通信，因为要保活所有层的输出。

块版把 L 层分成 N 个块、每块 S 层：块内各层输出先求和成一个块表示，块与块之间只对这 N 个块表示做全注意力；块的第一个层用前面所有块作值，块内后续层额外带上本块的部分和；最后一层聚合全部 N 个块表示。显存与通信从 $O(Ld)$ 降到 $O(Nd)$，块结构还界定了推理时的状态规模，块间的并行结果与块内顺序部分和可以用在线软最大化（流式维护最大值的累加技巧）合并。经验上 N 取 8 上下能收回大部分收益；K3 把层分成 8 个块、每块 12 层，块内排三组「3 层 KDA 加 1 层 Gated MLA」，另有 1 层 Gated MLA 置于骨干末尾、保证最后一层做全局注意力；末块层数不满，69 层 KDA 与 24 层 MLA 相加正好是规格表里的 93 层。加上嵌入层一共 9 个块。

**宽度轴：Stable LatentMoE。** 专家池与每 token 激活数同时变大，会扩大专家专门化的空间；常规 MoE 把全维度的 token 表示喂给每个被选中的专家，通信与专家权重流量随路由多重度增长。LatentMoE 把模型宽度与路由专家宽度拆开：共享专家保留全宽路径做通用变换，专门化的路由专家在一个宽度为 ℓ 的紧凑潜空间里工作。K3 因此把通道混合扩到每层 896 个路由专家、每 token 激活 16 个，稀疏度（路由专家总数除以每 token 激活数）为 896÷16=56；潜空间宽度 3584，是隐维的一半；每层 2 个全宽共享专家；每个专家内部隐维 3072。博客作者交代了这条设计路径：最初的设想是 448 选 8，引入 LatentMoE 之后变成 896 选 16，稀疏度保持不变，总专家数的增加依然会加剧负载不均衡。层结构沿用 DeepSeekMoE 的共享加路由组织：

$$
\boldsymbol{u}=\sum_{i\in\mathcal{T}_k(\boldsymbol{x})}p_iE_i^{\mathrm{routed}}(\boldsymbol{W}^{\downarrow}\boldsymbol{x}),\qquad \boldsymbol{y}=\sum_{j=1}^{N_s}E_j^{\mathrm{shared}}(\boldsymbol{x})+\boldsymbol{W}^{\uparrow}\operatorname{RMSNorm}(\boldsymbol{u}),
$$

路由路径先降维到潜空间、把潜表示发给被选中的专家、把加权聚合结果经 RMSNorm 与升维投影映回全宽。极端稀疏放大常规设计的两种失效：第一，路由路径把降维矩阵、门控多分支专家网络与升维矩阵连成接近四个连续的矩阵乘，条件数（衡量一串矩阵乘把输入幅度放大多少倍的量）差，小幅扰动会被放大成大幅激活，在 2.8 万亿参数规模下产出爆炸的内部激活；第二，将近一千个专家的负载均衡超出了既有免辅助损失偏置更新能稳定工作的范围。K3 用三件稳住它：升维前的 RMSNorm、SiTU-GLU、分位数均衡。

**升维入口的 RMSNorm。** 原版 LatentMoE 直接把升维矩阵作用在聚合后的路由表示上，该表示的尺度随选中的专家与路由权重变化；K3 在专家聚合与升维投影之间插入一层 RMSNorm，降低路由分支在与全宽共享分支合并前对尺度变化的敏感度。报告说它除了稳定训练，还一致地改善验证损失与下游基准。博客作者补充了来处：原始设计在降维之后与升维之前各放一个 RMSNorm，消融显示升维前那个作用最本质，按最小改动原则只保留它；更仔细的对照实验显示，在大家都能正常收敛的情况下，加不加这个 Norm 对验证损失影响不大，对某些基准则不加会稳定变差。他给出两个可能来源：一是它更好地平衡了路由专家与共享专家的比例（实测加了它之后不再需要额外的缩放因子），二是归一化本身是很弱的非线性，加入后无形中增加了 LatentMoE 的等效深度。

**SiTU-GLU。** 常规 GLU（门控线性单元）用一个 Sigmoid 门控去调制一条线性值分支；SwiGLU 把 Sigmoid 门换成 $\operatorname{Swish}(x)=x\operatorname{Sigmoid}(x)$，在 Transformer 里表现很好。SwiGLU 的两个乘数都无界，位置重合的大坐标会产出激活异常值，在低精度算术里有溢出风险。K3 提出的 SiTU-GLU 把平滑压顶 $\operatorname{softcap}(x,\beta)=\beta\tanh(x/\beta)$ 分别加到 Swish 门的线性因子与升维分支上：

$$
\operatorname{SiTU\text{-}GLU}(\boldsymbol{x})=\left[\beta_1\tanh\!\left(\frac{\boldsymbol{W}_g\boldsymbol{x}}{\beta_1}\right)\odot\operatorname{Sigmoid}(\boldsymbol{W}_g\boldsymbol{x})\right]\odot\left[\beta_2\tanh\!\left(\frac{\boldsymbol{W}_u\boldsymbol{x}}{\beta_2}\right)\right],
$$

取 $\beta_1=4$、$\beta_2=25$。缩放后的 tanh 在原点附近近似线性，在大幅输入下有界：局部展开是 $z+O(z^3/\beta^2)$，在原点附近与 SwiGLU 一阶相同，$\beta$ 趋于无穷时逐点回到 SwiGLU；每个输出坐标满足 $|\operatorname{SiTU\text{-}GLU}(\boldsymbol{x})|_\infty\le\beta_1\beta_2=100$。报告说平滑压顶在饱和边界之外仍保留非零梯度：饱和边界指 tanh 输出贴近 ±1、响应曲线走平的那一段，硬截断越过界限后梯度为零，平滑压顶在界限之外给出趋近于零的非零梯度。

![[raw/2026-07/cs.CL/arXiv/kimi-k3/assets/kimi-k3-fig4.png]]

图：GLU、SwiGLU 与 SiTU-GLU 的门控分支、升维分支与标量响应曲线。三条曲线共用 $x\in[-10,100]$ 的定义域，插图放大原点附近。SiTU-GLU 取 $\beta_1=4$、$\beta_2=25$，在原点附近贴合 SwiGLU，在大正输入下收敛到 $\beta_1\beta_2=100$。图取自《Kimi K3》正文。

博客作者交代了这条改动的原始问题：$\boldsymbol{W}_1$ 的某一行与某个输入同向时，输出 $\boldsymbol{w}\cdot\boldsymbol{x}$ 会非常大，极端情形下同样的事情在 $\boldsymbol{W}_2\boldsymbol{x}$ 上同时发生且位置相同，中间部分因此出现 $O(\|\boldsymbol{x}\|^4)$ 级的异常值。他先把 SiLU 换成 SiTU，把门控部分控制在 $(-\beta,\beta)$ 内（$\beta=4$），压测后发现这仍不能完全杜绝膨胀，于是把线性分支也加上压顶，形成如今的 SiTU-GLU。GPT-OSS 与 DeepSeek-V4 已经用过硬截断；在同样的界限下，他发现平滑压顶往往效果更好，所以选了平滑压顶。

**分位数均衡。** K3 走免辅助损失的路由，负载均衡靠给路由分数加一个专家偏置：路由分数取 $\boldsymbol{s}_i=\operatorname{Sigmoid}(\boldsymbol{W}_r\boldsymbol{x}_i)$，按 $\boldsymbol{s}_i+\boldsymbol{b}$ 做 Top-k 选择，混合权重 $p_{i,j}$ 用原始分数归一化，偏置只调节派发，不改变混合权重，也不进入路由器的梯度优化。原版偏置更新的固定步规则是 $b_j^{(t+1)}=b_j^{(t)}+\gamma\operatorname{sign}(\bar{\ell}-\ell_j^{(t)})$，其中 $\ell_j$ 是专家 j 在当前批收到的 token 数、$\bar{\ell}$ 是各专家平均收到的 token 数，步长 γ 在适应速度与负载振荡之间取舍。路由专家池涨到 896 之后，维持均衡变得困难；路由不均衡会拖慢专家并行（把专家分散到不同设备上）训练，并让部分专家得不到充分训练。

分位数均衡（Quantile Balancing，QB）把每个专家的偏置直接钉到与目标负载匹配的路由分数分位数上（把一批数值从小到大排序，落在某个比例位置上的取值就叫那个比例的分位数）。设一个训练批有 m 个 token、n 个专家、每 token 选 k 个，目标负载是每个专家 $q:=mk/n$ 个 token。做一次前向就够：在带偏置的分数上把 Top-k 换成 Top-(k+1)，前 k 个是实际走的路由，第 (k+1) 个是 token 要进 Top-k 必须越过的截断值 $\alpha_i$。边缘量指某个 token 的路由分数减去该 token 的截断值，即 $\boldsymbol{s}_{i,j}-\alpha_i$。固定截断值，专家 j 在候选偏置下收到的 token 数随门槛单调下降，把门槛设到 q 就让第 (q+1) 大的边缘量落在门槛上；把目标负载这个整数除以批内 token 数得到比例 $q/m=k/n$，连续分位数的定义直接套在离散计数上，于是这个门槛就是专家 j 这一列边缘量的 $1-k/n$ 分位数。更新写成

$$
\widehat{b}_j^{(t+1)}\leftarrow-\operatorname{quantile}_{1-k/n}\!\left(\boldsymbol{s}_{:,j}-\boldsymbol{\alpha}^{(t)}\right),\qquad \boldsymbol{b}^{(t+1)}\leftarrow\widehat{\boldsymbol{b}}^{(t+1)}-\operatorname{mean}\!\left(\widehat{\boldsymbol{b}}^{(t+1)}\right)\mathbf{1}.
$$

公式外面的负号是这么来的：所需偏置 $r_{i,j}:=\alpha_i-s_{i,j}$ 与边缘量相差一个负号，边缘量大的位置正是所需偏置小的位置，$r_{:,j}$ 的 $k/n$ 分位数与负的 $(\boldsymbol{s}_{:,j}-\boldsymbol{\alpha})$ 的 $1-k/n$ 分位数是同一个数。旧偏置只通过截断值进入更新，第二行减掉公共偏移，Top-k 选择不变。因果性上更新只在下一步生效，一个批不会用由它自己导出的偏置来路由。推理时偏置冻结。

图：分位数均衡示意，8 个 token、4 个路由专家、每 token 选 1 个。左图按 Top-k 路由得到负载（4, 3, 1, 0），深色圆圈是过热专家，浅色与虚线圈是闲置与濒死专家。中图每一列是一组边缘量（该列的路由分数减各自 token 的截断值），红色虚线画在 $(q+1)$ 大的边缘量处，让恰好 $q=2$ 个边缘量落在它上方，星号标出减去列偏置后每行的 Top-k 选择。右图是重排后的均衡负载（2, 2, 2, 2），红边是 QB 改动的分配。图取自《Kimi K3》正文。

报告的附录 C（Derivation of Quantile Balancing）给出对偶推导。均衡分配可以写成一道带约束的最优化问题：给每个 token 挑出恰好 $k$ 个专家、并让每个专家恰好收到 $mk/n$ 个 token，使被选中分数的和最大；这是一道线性规划（目标与约束都是线性的最优化问题），把 0-1 变量放松到区间上不会改变最优值（可行域是二分图的 $b$-匹配多面体——$b$-匹配指每条边至多出现一次、每个 token 侧度数为 $k$、每个专家侧度数为 $mk/n$ 的约束；这个多面体的顶点自带 0/1 取值，所以放松后的最优解仍落在整数点上）。引入 token 侧与专家侧等式约束的乘子（两个乘子分别是 token 与专家两侧的门槛），用 Minimax 定理交换优化次序，内层最大值逐项可分，得到凸对偶目标 $\mathcal{L}(\boldsymbol{\alpha},\boldsymbol{\beta})=\sum_{i,j}\max(0,s_{i,j}-\alpha_i-\beta_j)+k\sum_i\alpha_i+\frac{mk}{n}\sum_j\beta_j$；对两个乘子交替做精确坐标极小化，token 侧与专家侧的解都是同一个 $1-k/n$ 分位数，方法因此得名。路由只需要专家门槛（等价于偏置 $\boldsymbol{b}=-\boldsymbol{\beta}$），token 侧门槛与动态训练批绑定并丢弃，训练与推理的一致性因此保住。

报告把 QB 与上一代更新接在同一目标上：专家侧子问题的次梯度（目标函数在该变量上的斜率）正好是目标负载减实际负载，SignSGD 一步只保留这个负载误差的方向，QB 直接跳到同一对偶目标的精确坐标极小点（固定其余变量、只对这一个变量取到最小值的点）。这个视角解释了 QB 为什么无需学习率式超参，也解释了它在将近一千个专家时仍能在少数几步内收敛。带不等式约束的近邻方法（BIP）会给两个更新各加一处负值截断，只压制过选专家，对欠选专家没有推动，报告说实测均衡明显变慢。另一条 Expert Threshold 路由维护指数滑动平均门槛，并允许每 token 选中数变化。

**直方图估计。** 全批分位数要跨数百万 token、跨数据并行 rank 与梯度累积步聚合（rank 是并行训练里的一个设备进程，数据并行指各设备持同一份模型、各跑一份数据，梯度累积指攒几个小批的前向反向再更新一次参数），精确求分位数在训练循环里不可行。K3 改为每个专家维护一张分 bin 直方图。它直方图化的是「所需偏置」$r_{i,j}:=\alpha_i-s_{i,j}$，即把专家 j 恰好放到 token i 截断值上的偏置；所需偏置与边缘量相差一个负号，边缘量大的位置正是所需偏置小的位置，QB 的目标偏置因此是 $r_{:,j}$ 的 $k/n$ 分位数。分 bin 区间由当前偏置界住：路由分数是 Sigmoid 输出，落在 0 到 1 之间，截断值是某个专家的带偏置分数，落在 $b_{\min}$ 到 $1+b_{\max}$ 之间，于是每个 $r_{i,j}$ 都落在 $[b_{\min}-1,\,b_{\max}+1]$。这个区间均匀分成 B 个 bin，区间每步重算，bin 宽 $w=(b_{\max}-b_{\min}+2)/B$ 随偏置展开自适应。每次前向各 rank 把本地 $r$ 散布累加进每专家的计数矩阵，微批（一次前向处理的小批）之间不通信；步末一次整数 all-reduce（各副本把本地量求和后广播回每个副本）汇总计数，各 rank 从同一份汇总计数里读回分位数：选累计计数首次达到 $\lceil q\rceil$ 的 bin，在 bin 内线性插值。三条性质：累计计数在 bin 边界上精确，真分位数与估计落在同一个 bin 里，误差以 bin 宽为上界，$B=1000$ 时至多几个 $10^{-3}$，报告说没有观察到可测的残余负载不均衡；通信只有每层每步 $nB$ 个整数的 all-reduce，与 token 数 m 无关，报告说低于「每个微批在进程组里交换原始边缘量」这一自然替代做法开销的 1%；计数可加使全局直方图对分片方式完全不变，估计的是全局批的分位数，跨步对分位数做指数滑动平均还能压低批间采样噪声。

博客作者给出三条工程判据：K2 用的是 SignSGD 式免辅助损失更新，专家总数涨到 896 之后不够稳；QB 在数学上更合理，并且没有额外超参；分 bin 落地时，10000 个 bin 相对 1000 个 bin 对负载均衡没有更好的增益，分布的可加性让分布信息能跨机、跨梯度累积地以极低通信量聚合。

**视觉通路。** K3 原生多模态：文本、图像、视频在同一段上下文里由同一个共享骨干处理，没有事后的模态对齐阶段。编码器 MoonViT-V2 与既有做法的一个关键差别是它以自回归下一 token 预测从零训练，而 Kimi K2.5 一类做法从 SigLIP 一类对比预训练模型初始化视觉编码器（对比预训练用配对的图文把正样本拉近、负样本推远，训出的编码器擅长全局语义）。报告给出的首要理由是训练稳定性：把一个预训练编码器接到语言模型上做联合优化时，SigLIP 初始化的 MoonViT-3D 持续出现更高的梯度范数与频繁尖峰，从零训练的 MoonViT-V2 全程稳定。下一 token 预测还让编码器的表示直接由语言建模目标塑形。报告说 MoonViT-V2 在视觉评测上追平了 SigLIP 初始化基线，并据此判断对比预训练作为多模态语言模型的初始化在大规模上没有必要性。架构上它是 27 层视觉 Transformer、约 4 亿参数，用 RMSNorm，线性与注意力投影去掉全部偏置项；图像与视频共享参数；注意力分解为帧内空间与帧间时序两遍，时序方向另做池化压缩；投影前用 2×2 的像素重排把视觉 token 数降到四分之一，使边长最大 3584 像素的输入在 100 万 token 上下文里可以承受。

![[raw/2026-07/cs.CL/arXiv/kimi-k3/assets/kimi-k3-fig6.png]]

图：预训练消融里视觉塔的梯度范数。蓝线是 SigLIP 初始化的 MoonViT-3D，红线是从零训练的 MoonViT-V2；右图放大 1.4 万到 1.6 万步这一段。从零训练的编码器梯度范数更低、尖峰更少。图取自《Kimi K3》正文。

**优化器：分头 Muon。** K3 沿用 Muon 做矩阵参数的优化器，注意力投影上再细分成分头版本：对完整 Q、K、V 投影矩阵做牛顿-舒尔茨正交化时，改为沿头维度切开动量矩阵、对每个头的块单独正交化。报告的直觉是，整矩阵正交化把全部头当成一个耦合的块，梯度或动量尺度大的头会支配共享的更新方向，尺度小的头拿到的更新归一化不足；分头正交化把更新尺度在头间拉平。报告说这条改动带来更均衡的学习动态、更大规模下更好的训练稳定性，并且略微降低优化器开销，因为对高的分头块做牛顿-舒尔茨迭代比在完整投影矩阵上做更便宜。博客作者说这个改动在效果上没有优势，采用它的动机是正确性：每个头本就相对独立，不应耦合在一块。

**预训练数据与训练配方。** 这一节的改动集中在数据侧，训练设置沿用上一代。文本侧是四个域（网页文本、代码、数学、知识）加一个大规模视觉语料，每个域用规则启发式、分类器质量打分与去重联合过滤，采样率由小模型上的消融决定；知识与数学沿用上一代的改写配方，用风格与视角多样的提示、分块自回归生成、对源文档做保真核验。视觉侧沿用 Kimi K2.5 的分类法，把开源集合与自建流水线合起来，训练里坐标监督同时给绝对值与归一化到 0 到 1 的形式，并把代码片段与它们的渲染结果成对放进 SVG、3D 资产、网页、游戏、CAD 等领域格式，程序化多模态数据因此大幅扩充。训练设置没有新东西：优化器用分头 Muon 加上一代的权重裁剪，负载均衡用 QB，学习率走余弦衰减配 1% 线性预热（预热指训练开头把学习率从很低按线性升到目标值），权重衰减 0.1；训练从一开始就联合优化语言与视觉 token，没有事后插视觉编码器的阶段，预训练从 8K 上下文开始，后续阶段扩到 64K。

**scaling 律。** 架构、数据与训练改动一起改变了最优训练区间，报告为此重调批大小、学习率、每参数 token 数与模型形状，在留出的域外验证数据上画出拟合曲线，给出相对 K2 约 2.5 倍的整体 scaling 效率增益（同一验证损失下省下约六成算力）。学习率调度上，报告在固定最小学习率的前提下比较余弦衰减与「预热加稳定再加衰减」，并指出两种调度各自的最优超参差别很大，用同一组超参比较会因对齐程度不同而产生偏向，因此对每种调度各做一次独立的 scaling 律搜索；在各自最优设置下余弦衰减的最终损失更低，K3 据此把余弦衰减定为默认。

**长上下文扩展。** K3 走 NoPE，位置信息由 KDA 的循环门控与衰减隐式提供，因此直接外推到 100 万 token，不需要改位置编码。长上下文数据侧先清洗：自然来源的长文档与视频里有大量近似重复、二进制块、截断文件与无效日志，用精确与模糊去重、对视频帧做感知哈希、启发式与分类器质量过滤、结构校验组合处理；真正长而连贯的文档与视频相对稀缺，因此上采样，避免冷却阶段的长上下文分布被短序列淹没。长度本身并不自动带来长程能力，报告另外合成长上下文数据，用精心排列拼接的多模态文档与子任务，构造出解出时需要跨越整个 100 万 token 上下文读取散落信息的任务。窗口按四阶段课程渐进扩展：预训练阶段从 8K 到 64K，冷却阶段从 256K 到 100 万；昂贵的长序列计算集中在总训练预算的一小部分里，课程因此经济。

**后训练三段。** 第一段监督微调（SFT）建立后续强化学习的高质量冷启动策略：数据集在上一代基础上扩充，复杂智能体任务的覆盖大幅变宽，轨迹用上一代 Kimi 系列里的领域专精模型合成，再经多阶段验证与人工在环标注；所有数据用 K3 自己的 XTML 对话模板序列化。从 SFT 起就做量化感知训练（在前向里按低位格式算，让参数适应量化误差），专家权重用 MXFP4（一种四位微缩放浮点格式），激活用 MXFP8。

第二段强化学习在三个大域上展开：通用任务（通用体验、视觉、推理、忠实性、搜索、知识工作）、通用智能体（长程助理、深度研究、段落级写作）、编码智能体（软件工程、编码体验、内核任务、网页开发）；每个域乘三档推理力度（low、high、max），得到九个专家模型。报告展示强化学习算力增加时公开与自建评测的分数与平均助手步数一起上升。算法上沿用同步框架的部分 rollout：每次迭代对 N 个提示各采 K 条完成，维持 N×K 条活跃轨迹；当完成比例达到 λ 时生成阶段暂停，让策略优化不等落后的执行，暂停的 rollout 入队并在下一迭代优先恢复，依靠沙箱基础设施；逐 token 正则项把策略更新限制在局部邻域内，使算法能容忍跨迭代的长程轨迹带来的数据陈旧。推理力度用每题预算控制：从冷启动模型估计初始 token 预算 $b_0(x)$，总 token 数超过 $\tau b_0(x)$ 的轨迹奖励置为 $-1$；通用任务数思考 token，智能体任务数累计输出 token（含推理轨迹与工具调用参数）；先在较大的 τ 上训出最高预算变体（仍设最大预算上限压住过度思考），再把 τ 退火到更小值得到高档与低档专家。不可验证的通用任务用智能体式生成奖励模型：保留上一代的锦标赛式组奖励与二元比较，裁判按强制流程读产出、生成评分细则、按细则给每个候选打分、把分数记进记分板；另用基于预算的冗长控制，输出长度超过冷启动估计的 σ 倍即判负，压低朝冗长方向刷奖励的空间。

第三段多教师在线策略蒸馏把九个专家合成一个模型：对给定域 d 与采样的力度档 e，用对应教师模型引导优化，逐 token 的蒸馏奖励是 $\operatorname{clip}(\operatorname{sg}(\log\frac{\pi_{\text{teacher}}}{\pi_{\theta}}),-R_{\max},R_{\max})$，stop-gradient 切断教师侧的梯度，$R_{\max}$ 限制极端优势信号；这条稠密奖励信号直接接进强化学习框架，因此也能用上部分 rollout 一类基础设施优化。报告说更细粒度的 top-k 蒸馏目标在收敛速度与最终表现上都没有明显优势。

**部署向的后训练。** 专家权重（占参数内存的主要部分）量化到 MXFP4，激活按 MXFP8 计算，非专家部件（注意力投影、潜空间投影、共享专家、路由器）保持更高精度；量化感知训练覆盖 SFT 与强化学习两段，rollout 与训练共用同一套量化方案，训练与推理的精度落差被消掉。草稿模型一侧：K3 预训练时带一个结构镜像骨干块的多 token 预测层，EAGLE-3 的草稿模型是单个解码器层、结构与这个层相合，于是把预训练的多 token 预测层微调成 EAGLE-3 式草稿模型，目标模型冻结，只更新草稿层与特征融合投影。训练按 EAGLE-3 的训练时测试协议展开七步；第一步之外目标侧最新位置的特征不可得，草稿消耗自己前面步骤的输出，模拟推理时的循环起草。草稿输入融合目标模型低、中、高三个层级的特征，分别取第 1、第 4 与最后一个注意力残差块的输出，拼接后用无偏置矩阵投影回隐维，初始化成 [0 0 I]，融合表示在初始化时与预训练时的高层特征重合，微调中逐步纳入低层与中层特征。投机解码的加速由每 token 接受率 $\sum_x\min(p(x),q(x))$ 决定（p、q 是目标与草稿的下一 token 分布）；对容量有限的草稿模型，最小化常规的 KL 替代目标并不能保证最大化这个接受率，报告因此直接优化接受率的负对数，称为 LK 损失（取自同名论文《LK losses: direct acceptance rate optimization for speculative decoding》，arXiv 2602.23881），$p$、$q$ 取温度 1，另不加真值交叉熵项。

**强化学习的任务合成与环境。** 统一的白盒强化学习环境把智能体脚手架表示成一批可配置、可组合的模块，涵盖工具接口、系统提示、上下文管理策略、技能、记忆、子智能体等；按配置组合可以实例化 Kimi Code、Claude Code、Codex、OpenClaw、Hermes 等主流脚手架，也能造全新脚手架；训练时对不同任务组动态构造不同脚手架配置。任务来源用自演化的层次化知识图谱：图谱是有向无环图，用智能体驱动的递归扩展生长，边一律从粗概念指向细概念，分支在被分配的智能体判断概念足够原子时停止；采样节点后把节点关键词与祖先上下文拼成查询，检索真实材料，再由合成智能体产出训练任务。可验证任务包括多步复杂信息检索、专业人士的日常流程（投行、数据分析、法律，在沙箱里跨几十到几百步完成交付物）、以及多步可验证的视觉推理：每条视觉轨迹在一个带 Python 解释器的隔离沙箱里生成，模型迭代地写代码裁剪、放大、变换输入图像、做精确计算或验证中间结果，并把执行输出（含生成的图像）当作新的观测。内核优化任务从单算子内核到融合大内核，来源是 Flash Linear Attention 一类高质量开源库，覆盖 CUDA、Triton、CuTe DSL、Gluon、ThunderKittens、TileLang 等多种编程路径与 BF16、FP8、FP4 等数值格式；奖励同时评正确性与性能，每个内核给一份 PyTorch 参考实现，数值误差超过阈值的解奖励为零，性能以专家实现为基准，追平得 0.5，逼近硬件屋顶线则向 1 增长；另有作弊检测系统惩罚 CUDA graph 重放、输入缓存、降精度等刷奖励手法。个人助理任务造了 Gmail、Notion、Slack、Canvas 等常用应用的拟真实现，保留真实语义，能在无外部接口与限流的条件下大规模复现；任务以真实职业流程为原型，智能体在多天持续演进的环境里工作，单个 rollout 可能涉及上千次工具调用与数百万上下文 token，每个事件由确定性规则或模型评审各自判定。自主执行任务（AET）给定初始状态、受限目标、基于工具的动作空间、执行预算与独立验证器，智能体只看目标、上下文、约束与验证接口；奖励基于验证器对最终环境状态的评估，报错由验证器判定，验证器类型含黑盒系统复现、定量因子发现、税务审计；防作弊靠把智能体与验证器隔离、公开诊断验证器配隐藏的留出验证器、限制提交预算并施加罚项。网页开发任务由专家整理，产物覆盖网站、交互游戏、3D 与 WebGL 场景、数据可视化、SVG、全栈应用，在容器化沙箱里用多种脚手架 rollout 以促进跨脚手架泛化，奖励由确定性检查（功能、结构、像素相似度）与内部奖励模型的评审两部分组成，构建失败、运行报错或伪造产物的项目奖励为零。

**基础设施：KDA 的算法与系统协同。** KDA 用固定大小的循环状态替换随序列增长的 KV 缓存，串行的状态更新与 GPU 偏好的宽而均匀的并行相冲突，在不同执行场景里表现为不同瓶颈。训练与前填充用 FlashKDA：分块形式块内并行、块间串行，朴素执行时两段交替会让 SM（显卡上的计算单元）空转，FlashKDA 是基于 CUTLASS 的分块 GPU 内核（kernel，在显卡上执行的一段函数），把块内计算与跨块状态传播重叠，把工作拆成 token 并行阶段与 head 并行递归并各自调度调优，性能明显好过 Triton 参考实现，并且作为 flash-linear-attention 的后端自动派发。单机内长上下文前填充用自动的 SM 级上下文并行（把一条长序列切到多台设备或同一设备内的多个计算单元上分头处理）规划器：张量并行（把同一层的矩阵按头或通道切开放到不同设备上）按头切分而从不缩短递归长度，在只持有少数头的 rank 上做超长序列前填充会让多数 SM 空闲；关键观察是每段的状态转移可以独立于入态求值并在之后精确复合，规划器于是把序列分到单机各 SM 上并行求段转移再合并，恢复每段的精确初始状态，全程在设备内、无跨设备通信。

跨设备的 KDA 上下文并行（KCP）另做一层：软最大化注意力要求 rank 间交换随序列长度增长的键值块，线性注意力把前文装在固定大小的循环状态里，既有方法利用可加递归在各 rank 上从零态求本地状态再在之前 rank 上求和恢复入态。直接求和对 KDA 不够，因为 delta 规则先用 token 相关的矩阵 $\boldsymbol{M}_t=(\boldsymbol{I}-\beta_t\boldsymbol{k}_t\boldsymbol{k}_t^{\top})\operatorname{Diag}(\boldsymbol{\alpha}_t)$ 作用在入态上再加当前写入，本地序列段的效应依赖进入该段的状态。KCP 把每段的效应分解成两个本地可算的量：一个作用于入态的累积转移，一个从零态本地生成的状态；rank 级更新可以结合地复合，每段入态由一个前缀扫描恢复。每个 rank 本地算累积转移与零态状态，各用一次 all-gather（各副本把自己持有的那片发给所有副本）交换；之后 rank i+1 按顺序处理前序片段重建入态。KCP 只需要一次固定大小的 all-gather 做状态同步，计算呈线性扩展。

**基础设施：三万亿级预训练。** 训练并行组合了流水线并行加虚拟阶段、专家并行、ZeRO-1 数据并行（各设备持完整参数、只把优化器状态分片存放）、流水线 ZeRO-2 梯度分片（把梯度也分片存放，ZeRO 是显存分片方案、编号越大分片的对象越多）与上下文并行；MoE 层的共享专家在专家并行 rank 上复制，专家派发与回收的 all-to-all 通信（各副本互相发送数据）与计算重叠。报告点出三个难题：token 负载在专家并行 rank 间不均衡；激活、梯度与优化器状态超出显存预算；视觉编码器的计算量高度可变且暴露在关键路径上。

MoonEP 解第一个。常规专家并行的 token 负载在 rank 间不均衡，计算不均衡拖慢吞吐，路由专家激活的动态形状还造成大量内存碎片。MoonEP 用动态冗余专家做到完全均衡。指派分配是这样的：每个 rank 自己持一段长度为 S 的序列（S 是每个 rank 本地的序列长度），段内每个 token 选出 K 个专家，于是这个 rank 有 S×K 份「token 交给某个专家」的指派发往各个 rank；完全均衡要求每个 rank 恰好收到 S×K 份指派（含它自己发出去的），使所有 rank 做等量计算；报告证明均衡方案总存在、每个 rank 至多 $E/R$ 个冗余专家（E 是专家数，R 是专家并行度），并证明这个上界基本紧，最坏情形需要 $\lceil E(R-1)/R^2\rceil$ 个，R 大时约等于 $E/R$。每个 rank 预留 $E/R$ 个冗余专家槽位就能保证规划始终可行。先行工作预置冗余专家数或施加单 rank token 上限，在没有可行方案时只能停下训练。规划本身用整数线性规划离线求代表情形的精确解作参照，再用一个近似最优、开销可忽略、始终守 $E/R$ 上界的 GPU 规划内核在线求。完全均衡还简化通信：融合的 permute/unpermute 算子由规划内核预先算好每个 token 的去向，token 直接发到远端 rank 上按专家分组的位置，通信缓冲的视图直接交给计算，省掉中间拷贝；最坏不均衡下 DeepEP 要 $S\times K\times R$ 的通信缓冲，MoonEP 只需固定的 $S\times K$。静态形状去同步：完全均衡使各层计算形状静态可知，逐层的 MoE 主机同步被消掉，也缓解主机侧内核启动开销。单 rank 内各专家的 token 数仍有偏斜，工作负载感知的调度器在启动前按当前 token 分布调整参数并在执行期间保持，参数由一个用硬件指标解析代价模型、离线自调标定的启发式选取；共享专家的 GEMM 派到单独流上与其它内核重叠。

第二个难题靠统一激活管理器与若干组件优化。激活管理器把每个为反向保存的张量关联到可插拔的存储后端，重算、量化、卸载与远端卸载只是这个抽象下的存储策略，能按张量粒度自由组合，策略由张量上的轻量标注声明、与模型代码解耦；重算在函数粒度进行，支持跨层重算；全部显存分配在主计算流上的单一内存池里，避免多流碎片与主机瓶颈，激活按层粒度预取回并与计算重叠。K3 里多数激活用分块 FP8 量化配卸载/远端卸载，逐元素算子配置重算。MoE 侧借 SonicMoE 的思路把置换概率的梯度重写成只依赖中间激活与上游梯度的形式，去掉反向对前向输出的依赖，代价是一次轻量逐元素计算；组 GEMM 前向只保存派发的输入，反向通过重算派发恢复，通信与组 GEMM 反向的一部分重叠。注意力残差侧基于块版做配套优化：块表示在边界层生成一次，被后续所有层共享并常驻显卡；整个注意力残差计算用检查点包住，每层为反向保存的激活与标准残差结构一致；流水线并行下用基于缓存的流水线通信，只在级间增量传输新生成的块，微批结束即释放。激活在流水线 rank 间的分布因预热而不均，用 Mooncake 传输引擎把激活远端卸载到其它 rank 的内存以均衡占用。梯度一侧用流水线 ZeRO-2 分片，分片梯度存到 CPU 内存以压低显存峰值，双梯度缓冲留在显卡上，跨数据并行归约进双缓冲后再累加进 CPU 分片。Muon 的牛顿-舒尔茨正交化需要完整参数矩阵，而分布式优化器把参数均匀分片在数据并行 rank 上；朴素做法每次更新前 all-gather 整个参数缓冲，显存与通信都吃不消，K3 改为每个 rank 用点对点通信只取自己拥有分片的对应部分，省掉完整参数缓冲，通信与计算按模型块缓冲的粒度流水。

第三个难题把视觉编码器藏进流水线气泡。长上下文多模态训练里大图与长视频显著拉长编码器计算并在设备间造成负载不均，报告把上下文并行扩到这类大样本：单张大图沿图块维度切到多设备，注意力用跨 rank 的 gather-KV 计算；再把每个上下文并行组分成若干子组，把多张大图按负载均衡分下去，使通信占比不随规模增长，大视觉样本的编码器时延与跨设备负载不均一起下降，剩余编码器计算被藏进流水线气泡。上一代引入的解耦编码器进程把视觉与文本训练拆到不同阶段并均衡正反向；K3 进一步分解视觉计算，把前几个微批的前向提前同步执行、其余前向排进流水线气泡，反向同理。

**基础设施：100 万 token 智能体强化学习。** 训练用共置强化学习把每次百万 token 实验控制在数百张 GPU 内，用部分 rollout 压低超长轨迹的尾延迟。长上下文 rollout 额外占用显存做 KV 缓存保留，与训练侧状态竞争。外部 KV 缓存池采用写回设计：活跃解码块留在显卡 KV 缓存，可复用的空闲前缀只在被逐出显卡时写回 CPU 内存里的外部池，下次复用前预取回来；KDA 状态与对应的 MLA KV 块一起卸载与预取，生命周期对齐；训练状态在迭代结束后卸载到 NVMe，rollout 迭代结束后释放池以避免与训练争用。rollout 自动节流调度器用活跃请求数、排队请求数、KV 缓存利用率等运行时信号动态控制送进推理引擎的请求数，早期 rollout 保持良好利用，KV 缓存压力升高时降低并发。非策略模型前向复用梯度缓冲：参考模型一类只做前向的模型权重留在 CPU 内存，需要时用策略模型的 FP32 梯度缓冲存储承载这一实例化，梯度真正算出时缓冲被覆盖因此安全；配合流水线 ZeRO-2 分片与卸载，每张卡只为两个虚拟流水线块保留梯度缓冲，参考权重逐块流进这两个槽位，一个做当前前向、另一个预取下一块。

沙箱侧另起一套。K3 后训练与评估同时用容器运行时、GPU 沙箱运行时与基于微虚拟机的 AgentENV。AgentENV 由三个设计目标驱动：高保真隔离——能力更强的智能体探索更激进、甚至尝试刷奖励，早期容器运行时里观察到智能体误操作引发的 Linux 内核（操作系统内核）崩溃与死锁，而复杂任务又需要接近真实环境的沙箱（挂载磁盘、跑容器、启动虚拟机），用 Firecracker 跑隔离微虚拟机提供容器运行时到不了的隔离与保真；灵活的沙箱生命周期——底层支持增量检查点与恢复，只保存在上次检查点之后被写脏的内存页，检查点时延低到 133 毫秒、恢复 49 毫秒，上层提供暂停与恢复（暂停的沙箱不占内存与 CPU，智能体等待模型推理的时间可占沙箱生命周期的 98%）、派生（从原沙箱的精确状态复制一个新沙箱、原沙箱继续跑，用于无副作用地做奖励判定）与快照（定期保存以备错误恢复）；高效率与高密度——工作中可能要在数秒内创建数万个各带独立镜像的沙箱，用 OverlayBD 镜像格式配自研 ublk 驱动、存储层共享与点对点传输做到大规模下亚秒级启动，用写时复制内存与页缓存优化把内存超分比做到实测最高 6.5 倍。K3 的训练与评估全程创建了 51,219,741 个沙箱、涉及 1,505,678 个镜像。AgentENV 与伙伴协作开源。

**基础设施：推理与服务。** 混合 KDA 与 MLA 架构维护两种本质不同的缓存，百万 token 上下文下要联合管理。KDA 感知的前缀缓存把固定大小的循环状态塞进与 MLA KV 缓存同一个分页块池，页统一到相同字节大小，分配、引用计数、逐出共用一套实现；页内各头的状态按头连续存放，每个头的字节流自成一体，作为跨节点传输的最小单位；预填充与解码拆分部署、两侧张量并行度不同时，重排放在传输路径上做，显卡侧不重排。块哈希前缀缓存按物理块粒度复用，这条耦合在 K3 上失效：块哈希要求所有层共用一个块大小，前缀命中还要求命中边界上的 KDA 状态已经持久化；KDA 层每条序列只有一个大的循环状态，状态快照只在稀疏边界上可承受，共享块大小因此被迫在 1024 到 6144 token 之间，哈希粒度也随之变粗，而 MLA 的逐 token 条目本身能容忍细得多的块。这么粗的粒度下缓存近乎无用：短于一个块的请求永远无法复用，分块前填充在跨过整块边界前不导出可缓存前缀。

K3 把两级粒度解耦：前缀哈希跑在 MLA 页内的细「哈希块」上（例如 512 token），物理块保持粗分配单位；KDA 侧反向对齐，检查点只保存在 MLA 哈希端点的一个稀疏子集上，那里是查找可能引用的位置。前填充时，未填满的 MLA 页按最后一个完整哈希块的链式哈希登记进前缀缓存索引，每个哈希覆盖它之前的全部哈希块，命中一个端点即认证到该端点为止的整个前缀，登记端点随页填充前移；每次前向之后 KDA 内核在最后处理过的哈希对齐位置持久化循环状态，检查点较大，被新请求推进取代的中间检查点回收，会话轮次边界上的保留下来供跨请求复用；缓存检查点是只读快照，命中时把状态拷进请求私有的运行状态再进入下一次前向，新检查点写进新槽位，对其它请求可见的检查点永不被原地改写。查找分两段：MLA 段按链式哈希匹配整个物理块，在第一个缺失块处回退到块内的哈希端点，使未填满的页也能命中；KDA 段要求候选边界在每个 KDA 缓存组里都有检查点，每个组维护独立的循环状态；命中是同时满足两段的最长边界，始终是哈希块的整数倍，从不要求是物理块的整数倍。报告中一个请求的前 2800 个 token 与缓存前缀匹配，但可复用边界受 KDA 检查点约束，实际命中点落在 6144 token 物理块内部的 $2560=5\times512$ 处，从该 token 起继续前填充：前 2560 个 token 零重算，2560 到 2800 这 240 个 token 虽与缓存前缀匹配、其后没有可用的 KDA 检查点，与其余后缀一起重算。

![[raw/2026-07/cs.CL/arXiv/kimi-k3/assets/kimi-k3-fig12.png]]

图：物理缓存块内部的细粒度前缀缓存。一个 6144 token 的物理块含十二个 512 token 的哈希块，蓝色是已缓存的 MLA 块，浅灰是空块；下方标记 KDA 检查点状态，空心圈是没有存检查点的边界，灰点是已持久化的检查点，橙点是 $B=2560$ 处的命中检查点。请求复用五个 MLA 哈希块与 $B$ 处的 KDA 检查点，此后继续前填充，前面这一段零重算。图取自《Kimi K3》正文。

并发调度下还有三处一致性约束，各由一种共享未填满块的具体失效模式定出：所有缓存组从一个共享空闲表取块，为某一组分配私有副本可能逐出另一组刚命中的块，因此每个命中块在分配任何东西之前先跨所有组钉住；拷进私有块在显卡上紧接着前向执行，在当前调度步内分配或登记的块仍会把前任所有者的字节交给读者，这类块在拷贝落地前排除在匹配之外；一个检查点要恢复请求就必须在每个 KDA 组里都存在，逐出某一组的检查点会原子地使其兄弟失效——一个检查点要么在所有组里可命中，要么都不。有了这些机制，K3 的混合前缀缓存达到与全注意力模型同样的通用性：任何共享前缀在任何 512 token 边界上可复用，与请求长度、分块方式、调度交错无关。

内核侧按模块分开优化。KDA 解码的瓶颈从挖掘并行转到管理每步原地更新的循环状态；基于投机解码（多 token 预测）时，验证拒绝一部分起草 token 后状态已越过最后一个被接受的 token，无法简单回滚，为每个起草位置保存状态快照又会成倍放大状态流量，在大批量的在线服务里这一项开销占主导。报告的做法是只缓存起草 token 的投影输入（远小于状态本身），在片上重建被接受 token 的状态，只写回验证通过与被奖励的 token 的状态，这条设计在同一时期并有工作独立提出；重放 token、奖励 token 与下一个起草窗口共享一个融合内核里的循环，覆盖短卷积、输入归一化、门控、KDA 递归与输出归一化；验证时延随验证 token 数亚线性增长并低于状态缓存基线；投影缓存不离开解码阶段，前缀缓存与预填充解码拆分因此仍按与非投机服务相同的数据负载工作。块版注意力残差按两阶段调度：一次批量的块间处理每块读一遍已缓存的块表示，之后每层用在线软最大化合并把块内部分和折进来；两个阶段的开销里访存都占相当比例，优化集中在访存效率上。前填充为避免在每个张量并行 rank 上物化块表示造成冗余显存，对激活用序列并行：把张量并行的 all-reduce 拆成 reduce-scatter（按片归约、结果各自留在对应副本上）与 all-gather，块内内核插在两个集合通信之间，作用在按序列分片的隐状态上，使每个 token 的块表示恰好在一个 rank 上物化。解码时把块间内核放侧流（显卡上另一条可与主流并行排任务的对列）上与主流上独立计算重叠，块内内核则融合简化：把注意力残差输出与部分和更新，连同其后的 RMSNorm，融合进前面那次张量并行 all-reduce，省掉一个专用内核。Stable LatentMoE 侧，潜空间 GEMM 做三件：把降维投影与 MoE 路由器融成一个 GEMM；把潜空间权重矩阵按 rank 分片并用 multimem store 指令把输出 all-gather 融进 GEMM 尾声；把通信与共享专家计算等算子重叠。路由专家在小批大小下退化成访存受限的权重流式读取，常规以 tile 为中心的内核在这类场景表现不佳，K3 因此基于 WarpDecode 的以 token 为中心的设计构建 MoE 解码内核：每个 warp（显卡上成组调度的一小队线程）负责一个输出神经元并直接从内存流式读相关权重，进一步把 warp 细分出更小的 lane 队伍（lane 是 warp 内的一条线程）、各自处理不相交的专家子集，再做一次 warp 级归约；权重布局离线预处理一次，大幅降低运行时反量化开销。

集群级调度两条。缓存感知的亲和调度：100 万上下文下典型的编码输入携带 40 万 token 前缀而只需要 4K token 的前填充增量，前缀命中比缺失便宜几个数量级，因此把请求路由到持有其前缀缓存的集群；亲和把会话绑定在单个集群上，该集群故障会中断其全部会话，于是用一致性哈希把每个会话钉在两个集群上，一个主集群服务其流量，一个预分配备集群在主集群故障时接管；备集群不持有该会话的前缀缓存，故障切换时要重新前填充，一致性哈希把不同会话的备集群指派均匀分散到整个集群群，这份重算工作被许多集群分摊，缓存局部性在常态下保留，单集群故障的影响有界。基于预算的准入控制：生产流量把 2K token 以下的短请求与最长 100 万 token 的超长请求混在一起，单请求成本跨约三个数量级，按平均请求做的容量规划、排队模型与速率配额全都失效；典型失效模式是一批长上下文请求占满算力，随后到达的短请求无法及时调度，全部流量的首 token 时延一起变差；K3 因此给不同请求类各分一份资源预算，突发长上下文流量最多消耗自己那一份容量，系统级服务目标不被拖累。

**评测口径。** 公开基准按四个能力轴组织：推理与知识（GPQA Diamond、CritPt、长上下文推理、全量 Humanity's Last Exam 带工具与不带工具）、编码（DeepSWE、ProgramBench、Terminal-Bench 2.1、FrontierSWE、SWE-Marathon、PostTrainBench、MLS-Bench-Lite、SciCode）、智能体（BrowseComp、DeepSearchQA、ResearchRubrics、Toolathlon-Verified、MCPMark-Verified、MCP-Atlas、AutomationBench、JobBench、GDPval-AA v2、AA-Briefcase、Agents' Last Exam、APEX-Agents、OfficeQA Pro、SpreadsheetBench 2、OSWorld 两个版本、SaaS-Bench、银行、法律与金融几套专业基准）、视觉（WorldVQA、OmniDocBench、PerceptionBench、Video-MME、MMVU、BabyVision，以及 MMMU-Pro、CharXiv、Math-Vision、ZeroBench 主集各自带与不带 Python 工具两档）。对照模型为 Claude Fable 5、GPT-5.6 Sol、Claude Opus 4.8、GPT-5.5 与 GLM-5.2，除 GPT-5.5 取 xhigh（该厂商推理力度设置里与最大档并列的一档）外都取最大推理力度；K3 全部取最大力度、温度 1.0，单步的知识与推理任务与不带工具的视觉任务用 top-p 0.95，智能体任务用 top-p 1.0。编码基准在三套脚手架里选一套：Kimi Code、Claude Code、Codex。报告在配置一节交代了几处口径：回退指模型在某些任务上未能按原设置产出时改由服务端另一条兜底路径给出答案，这部分产出计入分数、读数因此偏高；Claude Fable 5 的结果包含回退行为，SWE-Marathon 有 35% 的任务触发回退；GPT-5.6 Sol 的结果带潜在的网络安全护栏；SWE-Marathon 用的是 2026 年 7 月 9 日的 H20 校准分支，Docker 镜像、性能门与 GPU 任务的参考解都按 H20 重标，正确性与防作弊校验器保持不变；FrontierSWE 的支配分数按 2026 年 7 月 16 日的官方脚本从原始分数重算；PostTrainBench 用官方 Harbor 实现在 H20 上跑三遍取平均；BrowseComp 采用 30 万 token 触发的上下文压缩策略，用完整 100 万 token 窗口且不做上下文管理时 Kimi K3 得 90.4%；OfficeQA Pro 把整个 PDF 语料渲染成图像交给智能体，不提供机器可读文本；MCP-Atlas 在 500 题的公开子集、100 轮上限下评，裁判用 Gemini 3.1 Pro；AutomationBench 在 600 题公开子集上评；视觉分数取三遍平均，ZeroBench 主集按官方设置跑五遍；第三方读数引自 Artificial Analysis、Vals AI、LMArena 与 Agents' Last Exam 官方榜，时间在 2026 年 7 月下旬。

## 关键证据

**scaling 效率。** 报告在留出的域外验证数据上比较两代模型的拟合曲线，给出相对 K2 约 2.5 倍的整体 scaling 效率增益，即达到同一验证损失所需的算力约为上一代的四成。

![[raw/2026-07/cs.CL/arXiv/kimi-k3/assets/kimi-k3-fig7.png]]

图：K2 与 K3 的 scaling 律拟合曲线，横轴为训练算力（对数刻度），纵轴为验证损失。两条曲线的水平间距标出 2.5 倍效率增益。图取自《Kimi K3》正文。

**KDA 的数值范围。** 下界取 $g_{\min}=-5$，每个保留因子大于 $e^{-5}\approx 6.7\times10^{-3}$，16 token 一小块的累积对衰减落在 $(-80,0)$，倒数缩放因子小于 $e^{80}$，留在 BF16 动态范围内；对角块与对角外块因此都走稠密 Tensor Core 矩阵乘。报告说这条参数化与先行工作里的下界循环门控关系密切，点名 HGRN2（带状态扩张的门控线性循环网络）、Griffin（门控线性循环与局部注意力的混合）、RWKV-7 三件。

**分位数均衡的误差与通信。** 目标是边缘量的 $1-k/n$ 分位数（等价地，所需偏置的 $k/n$ 分位数）。直方图取 $B=1000$ 个 bin 时估计误差以 bin 宽为上界，量级为几个 $10^{-3}$，报告说没有观察到可测的残余负载不均衡；通信是每层每步一次 $nB$ 个整数的 all-reduce，与 token 数无关，报告说低于逐微批交换原始边缘量开销的 1%。博客作者实测 10000 个 bin 相对 1000 个 bin 没有更好增益。

**MoonEP 的冗余专家上界。** 报告证明均衡方案总存在，每个 rank 至多 $E/R$ 个冗余专家；最坏情形至少需要 $\lceil E(R-1)/R^2\rceil$ 个，R 大时约等于 $E/R$，因此这个上界基本紧。每 rank 预留 $E/R$ 个槽位即保证规划可行，训练不会因找不到方案而中断。

**前缀缓存的两级粒度。** 物理缓存块 6144 token，内含十二个 512 token 的哈希块；KDA 检查点只在 MLA 哈希端点的稀疏子集上持久化；命中边界是哈希块的整数倍，从不要求是物理块的整数倍。报告的例子在 6144 token 物理块内部的 2560 处命中，前 2560 个 token 零重算；请求的前 2800 个 token 虽与缓存前缀匹配，其中 2560 到 2800 这 240 个落在没有 KDA 检查点的边界之后，与后缀一起重算。

**沙箱时延与规模。** AgentENV 的增量检查点时延低到 133 毫秒，恢复 49 毫秒；暂停的沙箱不占内存与 CPU，智能体等待模型推理的时间可占沙箱生命周期的 98%；内存超分比实测最高 6.5 倍；训练与评估全程创建 51,219,741 个沙箱、涉及 1,505,678 个镜像。

**强化学习算力扩展。** 报告给出八组公开与自建评测在强化学习算力增长下的曲线，分数与平均助手步数一起上升，横跨编码体验、通用工具使用、网页开发、智能体搜索、专业流程、办公交付物、智能体图表理解与智能体视觉谜题。

## 局限与缺口

- 预训练总算力与总 token 数报告没有给出。报告给的是两代拟合曲线与 2.5 倍效率增益，训练规模只出现上下文长度与并行配置。同一代的《DeepSeek-V4.1-Flash》技术报告（arXiv 2609.19969，本仓精读页 [[deepseek-v41-flash-reading|DeepSeek-V4.1-Flash 精读]]）给出 45T token 一类账目，这一份没有可对照的规模读数。
- 2.5 倍效率增益由两条拟合曲线给出，报告没有把它分解到各个改动上。KDA 下界衰减、注意力残差、Stable LatentMoE 三件各自贡献多少、数据与训练配方的改动占多少，都没有单独消融。架构、数据、训练配方一起改，这条增益的归因因此做不出来。
- KDA 的三处改动（下界衰减、满秩输出门、上下文并行）里，下界衰减给出的是数值范围证明与一张参数化示意图，没有把它单独开关后对训练吞吐与最终损失的对照读数。对角块计算路径被去掉之后内核实际省下多少时间，报告只给「消除了逐位置对路径」这一句。
- 分位数均衡与上一代 SignSGD 式更新的对照落在对偶推导层面。报告说明两者是同一目标上的精确极小点与符号梯度一步，两代模型的实际均衡质量差异、收敛步数差异与对最终损失的影响都没有跨模型读数。直方图的区间每步重算，报告没有给出区间跳变对偏置连续性的影响分析。
- 直方图估计的误差界是 bin 宽，报告说没有观察到可测的残余负载不均衡。这条「未观察到」没有给检测口径与统计量；跨步对分位数做指数滑动平均能压低采样噪声，平滑系数的选取与它对均衡速度的影响都没有给。
- AgentENV 的时延与规模数字带场景，报告没有给出这些数字的硬件配置、并发水平与尾部分布。检查点 133 毫秒与恢复 49 毫秒是低值还是典型值，报告没有说明。
- 训练硬件与集群规模完全没有披露。报告给出并行组合与显存优化手法，没有给 GPU 型号、卡数、训练时长或能耗，复现与成本核算都缺基准。
- 评测口径的对照条件不齐：Claude Fable 5 在 SWE-Marathon 上有 35% 任务触发回退，兜底路径的产出计入分数、读数因此偏高，该基准上的领先幅度难以直接解读；GPT-5.6 Sol 的读数带潜在网络安全护栏，这条口径只作用于网络安全类评测，与 SWE-Marathon 分属不同基准；FrontierSWE 用 2026 年 7 月 16 日的重算脚本、SWE-Marathon 用 7 月 9 日前的 H20 校准分支，与第三方榜单官方读数的关系需要逐榜核对。自跑结果在三套脚手架里选最好的一套报，跨模型的脚手架归属由报告指定，脚手架差异与模型差异混在同一列里。
- 报告自报的弱项集中在研究级推理（CritPt 23.4）与部分计算机使用基准，报告给的方向是继续投入。弱项的原因分析报告没有展开，只有分数。
- 网络安全评估第一层的「约七成经人工复核确认为真」缺少复核样本量与抽样方式；第二层 36 题套件里内核轨道 20 题，两个模型都未解出其中四分之三，样本量小，38.9% 与 22.2% 的差距在 14 题对 8 题的尺度上置信区间很宽。

## 我的分析

以下判断由我给出，报告正文没有这样组织。

三条轴的说法值得记成一句可检验的话：K3 把「一个 token 能看见多少信息」沿三个方向各自松开——序列方向用 KDA 的固定大小循环状态把长程混合的成本从随长度增长压到常数，深度方向用注意力残差把逐层累加换成一个可选择的读取集合，宽度方向用潜空间专家把通道混合的参数量与每 token 的计算量解耦。三个方向的花费各自独立，改动也能各自开关，这套划分本身就是一组消融的骨架；报告用了 2.5 倍这一个总数，把分解留给了读者。

KDA 的下界衰减是《Kimi K3》里最可迁移的一件。它的动机落在内核上：分块形式要用累积衰减的倒数缩放键，无界倒数迫使对角块走逐位置对路径；把衰减对数压到 $(-80,0)$ 之后，倒数小于 $e^{80}$ 落在十六位浮点的动态范围内，整块计算因此能用同一种稠密矩阵乘。也就是说，一个数值范围的界换来了一条计算路径的消失。这条思路可以直接搬到其它带循环状态的线性注意力实现上：先问哪一步需要无界倒数（《Kimi K3》里是分块前向对键的倒数缩放），再问能否用一个有界的门控参数化把它关进目标精度。

分位数均衡与上一代的差别是「跳到解」与「沿误差方向走一步」的差别。报告在附录 C 里把两者放在同一个对偶目标上，专家侧子问题的次梯度正好是目标负载减实际负载，SignSGD 只保留方向，QB 直接取坐标极小点。对偶把两代方案连成一条线，也把「无额外超参」这句话换成了一条可读的机制：坐标极小点的位置由分位数唯一确定，与步长无关。直方图那一层是纯工程：把分位数换成计数，通信从随 token 数增长变成每层每步一个固定大小的整数 all-reduce，跨机与跨梯度累积的聚合因此可行。这条「先找与规模无关的充分统计量，再想怎么聚合它」的顺序，是可以从这一节抽象出来复用的一条方法。

SiTU-GLU 的位置不止在激活函数。$\beta_1\beta_2=100$ 给出的是一个逐坐标的范数上界，路由分支的四矩阵连乘在这个界之下，低精度量化与激活值的动态范围也随之有界。报告把它与量化感知训练放在同一代里，两条改动相互补：软压顶把前向的数值范围管住，量化感知训练让参数适应低精度误差。把上界写成一个可调的 β 乘积，也让「压多狠」变成一个与模型尺度无关的超参，这在专家数继续增长时仍然可用。

《Kimi K3》的重量有相当一部分落在基础设施这一侧。MoonEP 的 $E/R$ 上界把「预留多少冗余专家才够」变成一个带证明的常数，前缀缓存的两级粒度把 KDA 状态快照的稀疏性与 MLA 逐 token 条目的细粒度分开处理，AgentENV 的暂停与派生把等待模型推理的时间从沙箱占用里摘出去。这些部件各自都能单独引用，也各自能搬到别的混合注意力架构上。

跨论文的联系上，DeepSeek 这一代把注意力那条轴往后推：博客作者在《简单谈谈K3的MoE和Attention》里读的 DeepSeek-V4（arXiv 2606.19348）把 MLA 的解码形式（头维 512 以上、键与值共享的 MQA）直接拿出来当每一层的主注意力，再叠稀疏与压缩把计算与缓存压下去；相邻一代的《DeepSeek-V4.1-Flash》技术报告有自己的精读页（[[deepseek-v41-flash-reading|DeepSeek-V4.1-Flash 精读]]）。K3 走的是混合路线：四分之一的层保留 MLA，其余四分之三用 KDA 的固定状态，位置编码交给 KDA 隐式提供。博客作者给出的读法是，DeepSeek 的注意力是 MLA 解码形式的推广与升级，代价落在基础设施复杂度与激进稀疏的最优性上；他自己也不给路线优劣的结论。这一段值得单独记：两条路线在同一个季度各自开源，对照点落在两套成本结构的差别上：「混合注意力把全注意力层数压到四分之一」与「全层稀疏注意力」。

对上一代 MoE 负载均衡的连续性也可以直接接上：[[loss-free-balancing|Loss-Free 负载均衡]] 是 K2 用的那一步，[[quantile-balancing|分位数均衡]] 是《Kimi K3》里的精确解，两页合起来正好是对偶目标上的两个点。[[shared-expert|共享专家]] 与路由专家的比例问题在博客作者对升维入口 RMSNorm 的解释里出现，那条解释给出一个可做的对照：去掉归一化时用缩放因子补偿，与保留归一化让比例自然平衡，两者在验证损失与基准上的差别可以单独量。

可延伸的实验有几条。其一，补出 2.5 倍的分解：固定数据与训练配方，单独开关 KDA 下界衰减、注意力残差与 Stable LatentMoE 三件，量出各自在验证损失上的份额，同时量下界衰减对内核吞吐的实际收益。其二，把分位数均衡与 SignSGD 式更新在同一个规模下正面对照：896 个专家、同样的数据与算力，量均衡达到目标所需步数、跨训练损失的差、以及直方图 bin 数在 500 到 2000 之间的敏感性。其三，沿前缀缓存的边界做压力测试：构造反复命中前缀又反复缺 KDA 检查点的多轮会话，量恢复路径的命中率与首 token 时延分布，验证「任何 512 token 边界可复用」在并发调度下的兑现程度。其四，把 SiTU-GLU 的 β 乘积当成一个测试轴：固定模型与数据，扫 β 乘积从数百到数千，量异常值幅度、低精度训练稳定性与最终损失三者的折中，确认 100 这个取值在不同专家数与不同隐维下的适用范围。其五，把注意力残差的块数当成一个测试轴：N 取 4、8、16、L（整版），量显存、跨级通信与最终损失，检验「N 取 8 上下收回大部分收益」这条经验在多长序列与多大模型上成立。

报告最值得引用的一句判断是它对开源的定位：把预训练基座推到 3T 级这件事本身就是一条独立的轴，测试时算力那条轴上的进展无法替代它。这句话把「开源追上闭源」的讨论从单点评测挪到规模与成本结构上，也解释了《Kimi K3》为什么把一半篇幅给了并行、缓存与沙箱。

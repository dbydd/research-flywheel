# DeepSeek-V4.1-Flash: Pushing the Limits of KV Cache Compression 精读

- 本体：`raw/2026-09/cs.CL/arXiv/deepseek-v41-flash/`
- 摘要：[[deepseek-v41-flash-abstract|DeepSeek-V4.1-Flash 摘要]]

## 问题与做法

**要解的问题：输入侧的账。** 被精读的论文由 DeepSeek-AI 集体署名，2026 年 9 月 17 日提交到 arXiv 的 cs.CL（arXiv 的计算语言学分类），编号 arXiv:2609.19969v1。它要解的问题是长程 agent（智能体）带来的输入成本。agent 一次任务要反复调用工具，每一轮都把很长的上下文重新送进模型，负载因此以输入为主。文本进模型前切成 token（词元，模型处理文本的最小单位，一段词或子词算一个）。一次请求分两个阶段：预填充（prefill）把整段输入并行读一遍并留下注意力所需的中间量，解码（decode）逐 token 生成输出。注意力机制里，每个位置有一组 key 与 value 向量，注意力用一个 query 向量与各位置的 key 匹配、对各位置的 value 加权求和；生成下一个 token 时要访问前面所有位置的 key 与 value；把它们缓存下来避免重算，就是 KV 缓存（键值缓存），规模随上下文长度与层数线性增长。运行中的缓存落在 HBM（高带宽显存），可复用的部分落 SSD 与主机内存并靠带宽在两者之间搬运。报告把算力、存储、带宽三样列为主要瓶颈，压缩目标直接定在 KV 缓存本身。

**三条成本轴。** 报告把 KV 的成本写成三个相乘的维度：条目大小，即每个 KV 条目占多少字节；序列维度，即多少个原始 token 合成一个缓存条目；层维度，即多少层各自留一份缓存。前几代 DeepSeek 模型相继攻过前两维：DeepSeek-V2 的 MLA（多头潜在注意力）在注意力头之间共享一个小潜变量，压的是条目大小；DeepSeek-V4 的压缩稀疏注意力把每 $m$ 个 token 合成一个条目（$m$ 即压缩比），压的是序列维度，并把全上下文全局注意力与滑动窗口注意力搭配起来（sliding window attention，只让每个位置看它前面固定长度的一段），把长序列算力降下来。逐层复用这一维此前被四条并行工作分别碰过，四条都有名有姓：YOCO（Sun et al., 2024）让上半网络直接共享下半网络产出的 KV，IndexCache（Bai et al., 2026）复用 Top-K 索引（每个 query 选出的分数最高的若干条目的编号）以省掉索引器（给条目打分选条目的轻量网络）计算，YOIO（Sun et al., 2026b）把稀疏路由（决定每个 query 读哪些条目的选择过程）算一次共享给所有层，HySparse（Gao et al., 2026）让稀疏层复用全注意力层的 KV。报告的判断是：索引复用单独做省不下主 KV 存储，全局共享路由限制性能，混合设计仍要保留全注意力层，四条路都没有同时覆盖三个维度。本文的 Compressed Sparse Attention 2（压缩稀疏注意力第二代，CSA2）要三样一起动：主 KV、索引器 K、以及选出哪些条目的 Top-K 索引，都沿层复用。

**模型骨架。** DeepSeek-V4.1-Flash 是多模态 MoE（Mixture-of-Experts，混合专家）模型。Transformer 一层里注意力之后的前馈层被拆成若干并行的小网络，每个 token 只走其中几个，总参数量随专家总数增长、计算量随实际激活的专家数增长。模型有 40 层 Transformer，5120 维隐状态，拆成 20 层因果编码器与 20 层解码器（编码器把输入整段读一遍产出表示，解码器逐 token 生成输出；因果指每个位置只看它前面），另有一个 32 层、1024 维、patch（图块）边长 14 的视觉编码器与一个两层、5120 维的视觉投影器，图像与文本从一开始就一起预训练。主干参数 552B，另有 196B Engram 条件记忆参数（条件记忆指由输入 token 直接查表取回的记忆嵌入，与主干权重分开存放）；每 token 预填充激活 8B、解码激活 16B。前两层只跑滑动窗口注意力，其余 18 个编码器层跑压缩比 2 的 CSA2，20 个解码器层跑压缩比 1 的 CSA2（压缩比 1 表示不压缩序列维度，只做条目选择）。每一层都有注意力与 MoE，MoE 是 1 个共享专家加 384 个路由专家，每个专家中间层 2304 维，每个 token 激活 6 个路由专家再加上共享专家；路由打分走无辅助损失的偏置校正，图像与文本各维护一套校正偏置，避免两种模态的负载互相掩盖。

图：总体架构。左边是 20 层因果编码器（前两层 SWA，其余三组六层，每组首层 Full、其余五层 Reuse），右边是 20 层解码器（五组四层，首组首层 Full、其余四组首层 Reindex，各组其余层 Reuse）。CED 的箭头表示解码器的全局 KV 由编码器末层隐状态投影而来，Hierarchical Sparse Indexer 把解码器首个 Full 层选出的块送进 Candidate Pool，DSpark 挂在解码器输出之后。图取自《DeepSeek-V4.1-Flash》正文。

**CED：让预填充只跑一半层数。** Causal Encoder-Decoder（因果编解码器，CED）受 YOCO 的启发而来。常规做法里每一层都从本层隐状态算出自己的全局 KV；CED 把后 20 层解码器的全局 KV 改成由第 20 层（编码器最后一层）的隐状态投影出来，每层有自己的投影权重。这样预填充阶段只算前 20 层就能拿到后面 20 层的全局 KV。记序列长度为 $N$、层数为 $L$、滑动窗口大小为 $n_{\text{win}}$，长序列的预填充复杂度从 $O(NL)$ 降到 $O(NL/2 + n_{\text{win}} \cdot L/2)$，在 $N\gg n_{\text{win}}$ 时约等于 $O(NL/2)$，接近砍半。滑动窗口那一路保留逐层计算，解码器的窗口缓存仍由各层自己的隐状态产生，代价是预填充时要多处理 $n_{\text{win}}\times L/2$ 个 token；报告借 Chen et al.（2025）一项「注意力的有效感受野远小于理论窗口」的观察（《DeepSeek-V4.1-Flash》§2.2 引），只重放最近一个窗口的 token 来近似重建这部分状态。

**CSA2：三种模式与逐层复用。** 每个 CSA2 层静态分配三种模式之一，三种模式都自己算 query 与滑动窗口 KV，差别在怎么拿到主 KV、索引器 K 与 Top-K 索引。索引器是一个轻量打分器：用索引器 Q 与索引器 K 给候选条目打分，为每个 query 选出分数最高的若干条目，query 只在这些条目加上本层滑动窗口 KV 上做注意力，条目数上限在模型设置里取 512。报告把索引器 K 改成由主 KV 投影而来，去掉了前代压缩器里相邻条目重叠取源与绝对位置编码的做法，实现与训练都更省。

| 模式 | 主 KV 与索引器 K | Top-K 索引 | 本层执行的工作 |
|---|---|---|---|
| Full | 本层算 | 本层算 | 走完整路径：投影出主 KV、由主 KV 投影出索引器 K、跑索引器产生新索引 |
| Reindex | 复用最近一个 Full 层 | 本层重打分产生 | 用自己的索引器 Q 在复用来的索引器 K 上重新打分，在同一份主 KV 上选出新的 Top-K |
| Reuse | 复用最近一个 Full 层 | 复用最近一个产生过索引的层 | 直接按已有索引做稀疏注意力，不跑索引器 |

![[raw/2026-09/cs.CL/arXiv/deepseek-v41-flash/assets/deepseek-v41-flash-fig4.png]]

图：CSA2 的三种模式。绿色方块表示本层算出来的量，黄色方块表示从最近的 Full 层复用来的主 KV 与索引器 K，红色方块表示从最近的产索引层复用来的 Top-K 索引；三种模式都各自算 main Q 与 SWA KV。图取自《DeepSeek-V4.1-Flash》正文。

**层次化稀疏索引器：给后层收窄搜索域。** 逐层复用索引减少了索引器跑的次数，剩下的索引器仍在整段可见上下文上打分，超长上下文里这一步还是重。解码器里第一个 Full 层给每个块取块内最大分数，挑出分数最高的 2048 个块，每块 8 个位置，收集成最多 16384 个候选位置的候选池；后面的 Reindex 层只在这个池内打分并各自选自己的 Top-K，Reuse 层不重新选。候选池规模固定时，后层索引器每 query 要打分的条目数与上下文长度无关。这条机制在训练与推理里同样施加，后层索引器在它推理时会用的同一个搜索域里被优化；首个 Full 层仍在整段可见范围上过一遍。

![[raw/2026-09/cs.CL/arXiv/deepseek-v41-flash/assets/deepseek-v41-flash-fig5.png]]

图：层次化稀疏索引器。每个小方块是一个位置，绿色表示被选中的索引，蓝色矩形表示按索引器最大分数挑出的块。解码器第一个 Full 层选出自己的 Top-512，并用选中的块建立共享候选池，后续 Reindex 层在这个池内选各自的 Top-512。图取自《DeepSeek-V4.1-Flash》正文。

**FP4 主 KV 缓存：把每个条目再砍一半。** 主 KV 缓存改用四位浮点。格式取 OCP 标准的 MXFP4，尾数加指数的取值配比用 E2M1（1 位符号、2 位指数、1 位尾数），每 16 个通道配一个 E4M3 缩放因子，照 NVFP4 的做法但省掉它第二级全局缩放。报告算过动态范围：这个格式能表示到 $448 \times 6 = 2688$ 的绝对值（448 是缩放因子格式能表示的最大值，6 是 E2M1 的最大值；RMSNorm 是训练里稳定数值的归一化层），缓存里最大的 RMSNorm 权重幅度约 1，512 通道 KV 潜变量的 L2 范数上限约 $\sqrt{512} \approx 22.6$，旋转位置编码保持这个范数，训练里观测到的最大幅度约 10，因此省掉全局缩放没有可测的精度损失。量化放在旋转位置编码之后做，主 KV 用四位、滑动窗口 KV 保持八位（报告说后者对量化更敏感）。相比 DeepSeek-V4 的八位主 KV 缓存，这一步把存储几乎砍半，显存与卸载到 SSD 两侧同样。启用方式是在后训练里做量化感知训练（在训练前向里就按低位格式算，让参数适应量化误差）。

**SWA Bounded Replay：把持久缓存里的窗口 KV 拿掉。** DeepSeek-V4 的持久 KV 缓存里，滑动窗口 KV 占了近一半容量，而它的复用模式与持久缓存的长期保留策略不合：全局 KV 有长尾复用，滑动窗口 KV 只在会话内几分钟的窄窗口里有用，会话一结束就作废。DeepSeek-V4 技术报告提过 Zero SWA Caching，用重算代替存储，精确重建要重放 $L \times n_{\text{win}}$ 个 token（层数乘窗口），在生产里代价过高。DeepSeek-V4.1-Flash 的做法有两条：滑动窗口 KV 不再进持久缓存，改放一台机器 10% 主机内存切出来的分布式内存池，池子小但存活只有几分钟，过期条目立刻回收给新会话；全局 KV 仍留在持久缓存里，保证至少 72 小时。缓存命中但窗口 KV 缺失时走 Encoder SWA Bounded Replay，只重放缓存前缀的最后 $n_{\text{win}}$ 个 token，与未缓存后缀一起处理，重放段只重建窗口 KV、复用已缓存全局 KV。解码器一侧同样处理：每个预填充只重放提示的最后 $n_{\text{win}}$ 个 token，把它们的编码器输出过一遍解码器层，得到只用于解码、不进持久缓存的解码器窗口 KV。两条重放都接受近似状态，报告说这对回答质量的影响可以忽略，并且在后训练里模拟同样的重放，让模型适应推理时的近似。

**三件架构件。** 这三件都不动 KV 账，压的是每个 token 都要付一遍的固定开销——残差混合的访存、一层前馈的计算、解码的步数。Single-Pass mHC 改的是 mHC（多流残差）的输入混合：原版每层的混合系数由本层残差算出，混合要等整条隐维的归约完成，因此得再读一遍残差；Single-Pass 版的输入混合改用上一层算出的系数，本层每个隐维分块一算出来就能同时喂给输入混合与系数预测，依赖断掉之后一个 kernel 干完三件事。部署内核 Mega-mHC 把每层的激活内存读写从 $(4n+4)\,d$ 降到 $(2n+2)\,d$（$n$ 是相邻块之间维护的残差流条数、$d$ 是隐维），砍半。Engram 由输入 token 直接查表取回条件记忆嵌入，196B 参数均分两个模块放在第 1 与第 14 层（层号从 0 计数），N-gram 阶取 2、3、4，8 个哈希头，每阶嵌入维合计 2048，每头约 1600 万条表项，表项长度取互不相同的素数；嵌入表与键值投影用八位精度，确定性的寻址让嵌入可以在推理时经 RDMA（远端直接内存访问）从主机内存预取。相对前作它去掉了短因果卷积，理由是这个卷积的收益配不上推理栈里多出来的复杂度。DSpark 是投机解码件（先用一个小草稿器一次猜出若干个后续 token，再让主模型一次性验证）：3 层草稿器，滑动注意力窗口 128，一次前向并行给出 5 个草稿位的基础 logits，一个轻量马尔可夫头（按转移矩阵在草稿之间建模依赖）串起相邻草稿位，置信头预测每个位置的接受概率、据此估计前缀存活率，调度器结合引擎吞吐曲线为每个请求挑验证长度，目标是在当前系统负载下最大化整体 token 吞吐。它放在预训练之后单独训练，主干预先冻结；后训练阶段两者一起训，DSpark 的梯度不回传到主干。

**优化器：给 Engram 换掉 Adam。** Engram 的嵌入表、token 嵌入与预测头若用 Adam，优化器状态会把显存撑起来。报告改用动量更新加 Sinkhorn 均衡（对更新矩阵交替做行归一化与列归一化，把两个方向的均方根拉到接近 1，与 Muon 的牛顿-舒尔茨正交化同位置，都只需一个动量缓冲），并对有效学习率乘一个修正因子 0.18 来对齐 Adam 的更新幅度（Moonlight 里用的因子是 0.2）。Query 与 Key 的权重改成分头 Muon：原版 Muon 对所有权重用同一个预条件子，分头版按头拆开，照顾到不同注意力头的异质性。其余配置沿用 DeepSeek-V4：线性变换权重走 Muon，归一化层与非矩阵参数走 AdamW，解耦权重衰减与 Nesterov 动量。

**预训练与后训练。** 预训练这一段只有两个决定值得记：规模上，45T token 的多模态语料按文本与多模态 7 比 1 混合，batch（一次参数更新处理的样本量）固定 100.6M token，学习率预热 2000 步后保持 $2.6\times10^{-4}$ 到 28T token、28T 到 40T 之间按余弦衰减到 $2.6\times10^{-5}$ 后保持不变；路径上，稀疏注意力从零开始、在 64K 序列长度上直接训练，没有稠密注意力预热阶段，34T token 处把序列长度扩到 1M——报告没有给跳过热身阶段的风险读数。视觉件单独训两段：先用约 47B 图文对做 SigLIP 的 sigmoid 对比损失（一批图与文里正负对一起算 sigmoid 交叉熵，对比学习指把配对的图文拉近、不配对的推远），分辨率限制在 224；再把编码器接到一个 4B 的 MoE 语言模型上做 236B token 的自回归微调，分辨率在 544 与 1344 之间，训完丢掉语言模型只留编码器。后训练的改动全部落在数据与环境管线，报告明确说没有算法新意：监督微调、强化学习、在线策略蒸馏三步照旧，管线做的事是把每个任务写成「问题、环境、验证系统」三元组，以难度与正确性为奖励训练模型自己造任务，造出编码器与通用 agent 两套环境，再对任务做过滤、去重与难度校准；强化学习侧用异步生成与样本级调度器维持并发，用拼接式路由重放处理跨检查点的样本，并在训练里屏蔽陈旧度过高的 token。沙箱平台 DeepSeek Elastic Compute 撑到百万级并发实例，单机容器密度从约 1000 提到 2500 以上。推理力度做成 prompt 里一个 1 到 100 的标量，训练时按力度分层采样，长度惩罚系数随力度指数衰减，公开 API 分 max、high、low 三档，对应 100、75、50。

**评估口径。** 基座档只在内部框架里比，对手是自家前代 DeepSeek-V4-Flash-Base 与 DeepSeek-V4-Pro-Base，另在内部语料上比 bits-per-byte（每字节比特数，语言模型在留出语料上的编码代价，越低越好）。后训练档对齐闭源与开源外部模型，推理基准取温度与 top-p（按概率从高到低累计到阈值、在截断后的集合上采样）都为 1.0，编码 agent 基准用自家 DeepSeek Harness 的 Minimal 模式、1M 上下文窗口（harness 指模型外面那层提示词、工具定义与回合逻辑，报告后文称 scaffold），安全基准用 Claude Code harness，视觉 agent 用 Claude Code harness、512K 窗口；稳健性检验把六套 scaffold 的八种配置在固定模型与任务集上比一遍，并另跑四个版本的 Claude Code 看版本差异。缓解奖励作弊的手段是断网、剥掉 Git 历史、清理构建与包缓存；报告承认仍观察到模型反编译 Ubuntu 核心包去找漏洞这类行为。

## 关键证据

## 局限与缺口

- 报告自报的边界有两处：CSA2 的稀疏选择可能出错，SWA Bounded Replay 的窗口状态是近似重建，未测的极端输入与部署条件下可能掉能力。后续压力测试的方向列在长上下文稀疏检索与缓存恢复边界两条。
- 近似重建有一处报告自己写明的性质：重放段的窗口状态是近似的，因此未缓存后缀算出的全局 KV 与窗口 KV 依赖缓存命中位置，同一段文本在不同命中位置上算出的值不逐位相同。质量影响报告说是可以忽略，没有给出量化对照。
- 四分之一与八分之一这两个总账没有逐项分解表。八分之一拆成了「不放窗口 KV」与「全局 KV 再压到四分之一」两个乘数；四分之一这一层只说来自架构与精度两类优化，没有给出各件（逐层复用、FP4、压缩比、索引复用）的单独贡献。
- FP4 主 KV 的精度代价写作「只有边际退化」，精度对照表、各任务上的掉点幅度、以及去掉全局缩放后的消融数字都没有给出。省掉全局缩放的理由是动态范围算得过来，算的是理论上界（$\sqrt{512}$ 与观测最大值 10），换模型或换层分布后是否仍成立需要重算。
- 候选池的规模（2048 块乘 8 个位置等于 16384 个候选）与块内取最大值这条块级打分规则，报告只给机制与「固定池大小时，后层每 query 成本与上下文无关」的界，池大小的来源依据、以及尺度变化对召回的影响没有给出。
- 「三分之一总参数、四分之一激活参数」与表格里的数字口径不一致：表格里 DeepSeek-V4-Pro-Base 激活 49B，本模型解码激活 16B 约为它的三分之一、预填充激活 8B 约为它的六分之一；总参数 552B 对 1.6T 约为三分之一。
- 「保留评估集上 5% 到 10% 的提升」指的是内部语料的每字节比特数测试，公开基准表里本模型并未全面超过 DeepSeek-V4-Pro-Base：SimpleQA Verified（42.3 对 55.2）、MATH（61.1 对 64.5）、MGSM（80.2 对 84.4）、LongBench-V2（45.2 对 51.5）都低，MultiLoKo（45.5 对 50.9）与 BBEH（27.2 对 29.8）也低。逐项看，公开基准上的优势集中在多数选择题与代码题，知识密集与长上下文题的读数偏低。
- 基座档全部在内部框架里评估，对手全是自家前代；后训练档才引入外部模型。两套口径的比较基准不同，跨档比较数字时需要一个统一的读法。
- 后训练「没有算法新意、收益来自数据与环境管线」是一个因果主张，报告给出的证据是强化学习步数累积曲线（单 scaffold、同 scaffold 多变体、异构 scaffold 三种扩展）随步数单调上升，数据管线各件与算法改动的对照消融没有给出。
- 多智能体的结果报告自称是初测，比的是「观察到的最好多 agent 配置」与「可用的最好单 agent 基线」，两个口径的算力预算没有对齐说明。
- 多模态评估的对手不全：基座档的多模态项只有本模型有数，后训练档里 Chartography、BabyVision、ZeroBench 三项只与 Opus-5、GPT-5.6 Sol、Kimi-K3 比，GLM-5.3 与自家前代缺数。
- 报告结论里出现的 Fable-5 与 GPT-6 Astra 两个名字只出现在结论段，正文的表与正文别处都没有这两个模型的数据，读者无法核对这句「接近顶尖模型」的具体所指。
- 报告的参考文献里 Engram 占两条同题条目：预印本与 ACL 2026 正式版各一条，两个键在正文不同小节混用；同一对象两个引用键，读者要在两条之间自行判断。
- 报告自述走的是自家模型线的推进，架构侧的前作只点到与本文直接相关的四条并行工作与三件组内前作，更早的长上下文压缩谱系是选择性的。

## 我的分析

以下判断由我给出，报告正文没有这样组织。

三条成本轴相乘，这个写法值得记。KV 成本等于「条目字节数 × 压缩后的序列长度 × 存缓存的层数」，三个因子各自独立可乘，压缩比也就能直接相乘读出来。DeepSeek 这条线的前几代各攻一个因子，CSA2 第一次把三个一起动。按报告给的两个乘数做一次算术核对：持久缓存压到八分之一等于「不放窗口 KV」（约二分之一）乘「全局 KV 压到四分之一」；再往下拆，主 KV 从八位降到四位「几乎砍半」，剩下的一半只能来自逐层复用与索引复用，这一层报告没有给数。这套乘法关系本身就是一条可检验的预测：若某层的复用链断掉（Reindex 层比 Reuse 层多一份索引选择），它对该因子就不再贡献压缩。

CED 的取舍值得单独看。解码器的全局 KV 由编码器末层隐状态经每层各自的投影得到，好处是预填充只跑一半层数，代价是解码器全局 KV 的表达力被固定在编码器末层那一份表示上，层的差异全部落在投影权重里。报告用近似重放换掉窗口 KV 的持久存储，也是在同一个方向上做取舍：存储省下来，读的一致性交出去一部分。两处叠加之后，同一段文本在不同缓存命中位置上算出的缓存值可以不逐位相同，这个性质对多轮会话、前缀共享与批处理调度的影响值得实测，报告只说对回答质量影响可以忽略。

DSpark 与稀疏注意力的配合是一个顺手的设计。草稿器的 5 个草稿位要一次验证，验证这一步要在主模型里对 5 个位置同时做注意力，读的是同一份主 KV 与同一套 Top-K 选择；Reuse 模式层的选择在层间固定、候选池在解码器首个 Full 层一次建好，验证批的读集合因此稳定。把投机解码接到稀疏注意力上时，选择的不稳定会直接变成验证代价的浪费，这一版的结构把不稳定性压在了少数 Reindex 层。

Engram 的处理是后训练之外少见的一处优化器改动。嵌入表与预测头这类「一行一个词或一个 n-gram、一列一个特征」的巨大矩阵，Sinkhorn 均衡沿两个轴各自归一化，只留一个动量缓冲，比 Adam 的两份状态省一半以上；报告用 0.18 的修正因子对齐 Adam 的更新幅度，这个因子来自 Moonlight 的 0.2，属于经验迁移。表项长度取互不相同的素数，是为了少出哈希冲突，属于实现细节里透露的确定性寻址诉求（确定性寻址才能让主机内存预取与 RDMA 传输排进流水线）。

可延伸的实验有几条。其一，把报告缺的分解表补出来：固定其余件、单独开关逐层 KV 复用、Top-K 索引复用、FP4 主 KV 三项，量出四分之一里各自的份额，同时量 FP4 的掉点。其二，沿着缓存恢复边界做压力测试：构造反复命中前缀又反复缺窗口 KV 的多轮会话，看近似重放的误差是否随会话轮数累积。其三，扫候选池规模与块大小（现在是 2048 块乘 8 个位置），量长上下文检索召回与每 query 成本的实际折中曲线，验证「固定池大小时成本与上下文无关」这条界在何种上下文长度上开始松动。其四，把推理力度这个标量接到多模态与 agent 轨迹上做交叉验证：报告说它在单轮推理上学到的控制能迁移到长程 agent 轨迹，八个基准的曲线平滑，值得在视觉 agent 与安全类任务上各补一组。其五，把 DSpark 的接受率与稀疏注意力选择的重合率分开量：草稿被拒的原因里，有多少来自草稿器本身的建模误差，有多少来自验证时稀疏选择与草稿时不一致。

报告最值得引用的一句判断是它对后训练阶段的结论：在固定的、平常的优化流程下，合成数据与环境的规模、多样性与可验证性几乎解释了全部收益。这句话把研究重心从算法挪到数据管线，也把可复现性的门槛挪到了数据侧——数据管线不开源时，算法侧的对照实验做不出来。后训练这一段的可复核性因此比架构那一段低。

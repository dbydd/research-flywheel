## 问题与做法

Qwen3.8-Flash-Next 是一个稀疏混合专家（MoE：每 token 只激活一部分专家网络）语言模型加视觉编码器的多模态模型：主干 125B 总参数、每 token 激活 6B，另有 51B 的 n-gram 嵌入表放在加速器显存之外的主机内存里、4B 的多 token 预测（MTP）参数，48 层，原生上下文 262,144 token，按 YaRN（把旋转位置编码的频率角度按因子拉长以覆盖训练期没见过的长位置）外推到 1,000,000。发布件 `config.json` 的架构类名写作 `Qwen4ExpForConditionalGeneration`、model_type 写作 `qwen4_exp`。

这份资源的双重身份要先摆清。它是权重发布件：Hugging Face 上可直接下载的模型。它同时是架构预览件：仓库 README 开篇写明，这一版放出的权重充当 Qwen4 所用架构的早期预览，角色等同于 Qwen3-Next 之于 Qwen3.5——那次引入的 Gated DeltaNet（下称 GDN）加门控注意力混合设计此后贯穿 Qwen3.5、Qwen3.6、Qwen3.7、Qwen3.8 四个系列，官方选择再次提前放出架构改动，让社区在完整 Qwen4 家族建在它上面之前先检验。模型卡另记一条产品线事实：API 服务上的 Qwen3.8-Flash 是基于 Qwen3.8-Flash-Next、加了更多生产特性（默认 1M 上下文、官方内置工具）的正式版本。

技术报告的设计目标写在摘要与引言：在 14 个预训练基准上，用约三分之一的激活参数、三分之一的训练 token、约九分之一的训练 FLOPs，保住上一代 397B-A17B 旗舰（Qwen3.7-Plus-Base）的质量。结果兑现：赢 8 项，其余 6 项最多落后 2.6 分。

报告的方法论主张比这组数字更承重。作者把每个候选架构改动同时放上三条评估轴：损失与下游基准一起看；改动在训练、前填充（prefill：把整段输入一次性算进模型）、解码（decode：逐 token 生成）三段的成本分开看；改动对最优超参与训练稳定性的影响单独看。报告全文的主语是「一处改动加三轴读数」，作者刻意把这些矛盾之处写进报告正文——损失与下游精度分道扬镳的地方、预训练指标干净、后训练才退化的地方、白花优化步的惯例。结论一节把这套协议拦下的三条「看似无害的捷径」列成清单：只在预训练无损的稀疏读写、在预训练看不出差别的位置编码删除、多花 18.8% 优化步的批量 warmup。

四处承重改动各对一个瓶颈：

|改动|对什么瓶颈|一句话机制|最重的读数|
|---|---|---|---|

## 关键证据

### 问题一：token 混合怎么分工——循环层压历史，稀疏层按块检索

**论点：这一代把「留多少全注意力、全注意力怎么变便宜」拆成两个独立决定，各自的消融都落在数字上。**

第一个决定是比例。线性注意力（把历史压进一个固定大小的矩阵状态、成本随序列长度线性增长的注意力替代件）负责高效压缩，每四层一个的全注意力层保留逐 token 的直接检索——报告的理由是任何有限状态循环记忆都精确复现不了这种检索。消融在 28 层 25B-A3B MoE 上做（记法说明：25B-A3B 即总参数 25B、每 token 激活 3B，下文同形；结构底座是 Qwen3.5 架构，先 4K 上下文训 400B token，再 32K 上下文训 80B token），九项基准（知识 MMLU、MMLU-Pro、SuperGPQA，数学 MATH、GSM8K，推理 BBH，多语 MMMLU，代码 EvalPlus、MultiPL-E）均值：全注意力 49.87，滑动窗口混合（窗口 128）51.15，GDN 混合 53.81。GDN 混合在九项里赢全注意力八项、赢滑动窗口七项，拿下九项里七项的单列最高与全场最高平均（MMLU 与 EvalPlus 两项的单列最高归滑动窗口档）。

第二个决定是 GDN 自身的配方。状态递推（每头独立，$q_t,k_t\in\mathbb{R}^{d_k}$、$v_t\in\mathbb{R}^{d_v}$、状态 $S_t\in\mathbb{R}^{d_k\times d_v}$，报告注明这是 Gated DeltaNet 原文状态约定的转置）：

$$
\widetilde{S}_{t-1}=\alpha_t S_{t-1},\qquad
e_t=v_t-\widetilde{S}_{t-1}^{\top}k_t,\qquad
S_t=\widetilde{S}_{t-1}+\beta_t k_t e_t^{\top},\qquad
y_t=S_t^{\top}q_t ,
$$

合并成 $S_t=\alpha_t\left(I-\beta_t k_t k_t^{\top}\right)S_{t-1}+\beta_t k_t v_t^{\top}$。衰减 $\alpha_t\in(0,1)$ 全局控制旧状态的寿命；delta 项先估计当前键 $k_t$ 已经关联的值，只把残差写回去，重复或相近的键因此更新既有关联、积累不起无界的外积。参数化：q/k 走短因果卷积加 SiLU 再加 L2 归一化（L2 归一化把 q/k 幅度封住，稳住秩一 delta 转移），v 走卷积加 SiLU；

$$
\beta_t=\sigma(W_\beta x_t),\qquad
\alpha_t=\exp\left[-\exp(A)\,\mathrm{softplus}(W_\alpha x_t+b_\alpha)\right],\qquad
o_t=W_o\left[\sigma(W_z x_t)\odot \mathrm{RMSNorm}(y_t)\right].
$$

两处改动带账。输出门：Gated DeltaNet 原文用 SiLU 门，本件换有界 sigmoid 门，报告称在全部实验里观察到一致提升（Gated DeltaNet 原文的消融表里去掉输出门把困惑度从 27.35 推到 29.12，这一件在原始配方里就是承重件）。归一化：沿用 Qwen3-Next 的 zero-centered RMSNorm（权重零初始化、前向乘 $(1+w)$，限制归一化权重的增长），全模型所有 RMSNorm 统一此式。发布件对账：GDN 线性注意力 V 头 48、QK 头 16、head_dim 128、短卷积核 4（`linear_conv_kernel_dim=4`）。

一处被点名的反直觉观察：全注意力层保留 RoPE（旋转位置编码：把查询与键按位置角度旋转，使内积带上相对距离）。RoPE 与去掉位置编码的 NoPE 变体在预训练阶段看不出差别，NoPE 在后训练之后 endless generation（停不下来的重复生成）率明显升高、更容易不终止。这条捷径在预训练指标上量不出差别，后训练的终止行为把它暴露出来。

继续预训练阶段引入 QSA，把骨干与 MTP 里的全注意力层全部换掉。索引器是一个 MQA（多查询头共享一个键头的注意力结构）：$H=4$ 个查询头加 1 个共享键头，查询侧带 RMSNorm、键侧不带：

$$
q_i^{h}=\mathrm{RMSNorm}(W_Q^{h}x_i),\qquad k_i=W_K x_i ,
$$

键按 $r$ 个 token 非重叠分块做平均池化压缩，位置编码在池化之后施加——每头 128 维里旋转 64 维，块取块首位置、查询保留 token 位置，报告给的理由是避免把不同旋转相位的 token 表示平均在一起：

$$
\bar k_b=\mathrm{RMSNorm}\!\left(\mathrm{AvgPool}(k_{p_b:p_b+r-1})\right),\qquad
I_{ib}=\sum_{h=1}^{H}\mathrm{ReLU}\left\langle q_i^{h},\bar k_b\right\rangle ,
$$

打分受块因果约束：只有满足 $p_b+r-1\le i$（块内最后一个 token 不晚于查询位置）的块可被该查询打分，否则记 $-\infty$。

给定 token 预算 $K$，块预算 $K_B=\lceil K/r\rceil$，选中的块展开成 token 下标、末尾不完整块的 token 恒包含。生产配置 $K=2048$、$r=4$、$K_B=512$，与发布件 `indexer_budget=2048`、`indexer_compress_ratio=4`、`indexer_n_heads=4`、`indexer_kv_heads=1`、`indexer_head_dim=128` 逐项对齐；核心注意力 `head_dim=256` 配 `partial_rotary_factor=0.25` 给出 $256\times0.25=64$ 个旋转维，报告正文「索引器旋转维与核心注意力模块的旋转维一致」这句话在发布件里成立。索引器复杂度从 $O(n^2)$ 降到 $O(n^2/r)$。

对照件要摆清（数字回一手渠道核过，见增强页）。DeepSeek-V3.2 的 DSA 是同路线先行件：token 级打分、64 个索引器查询头、每个查询选 2048 个键值 token——本件与它 token 预算同为 2048，改动在打分粒度（token 级移到 $r$ token 块级）与索引器头数（64 降到 4）。DSA 原文自陈其闪电索引器仍是 $O(L^2)$ 复杂度、靠少头与 FP8 压常数，报告 §2.1.2 的动机句与这一自陈对得上。蒸馏监督的两段协议照搬 DSA 的索引器 warm-up 参数：第一段只训索引器 1,000 步、学习率 $1\times10^{-3}$、每步 8 条 256K 序列、合计约 2B token，教师分布是全序列 softmax 注意力按教师头求和、L1 归一，再按 $r$ 做 max-pool 到块级、重新 L1 归一，索引器分数对块级教师做 KL：

$$
L_{KL}=\frac{1}{N}\sum_i D_{KL}\!\left(\hat a_{i,:}\,\|\,\mathrm{Softmax}(I_{i,:})\right);
$$

第二段骨干与索引器联合训 8,000 步、学习率 $2.5\times10^{-5}$、每步 96 条 256K 序列、合计约 200B token，KL 限制在选中的 $K_B$ 块上、教师概率在该集合内重归一。DSA 原文两段的 warm-up 是 1,000 步、$10^{-3}$、每步 16 条 128K、合计 2.1B token——第一段的步数与学习率是照搬，第二段的序列长度、学习率与预算是本件自己的配置。块级 max-pool 教师的归属要收窄：报告把这一步并写给 SeerAttention 与 ProxyAttn 两件，回一手渠道，把教师分布压到块级做 KL 目标的做法只见于 SeerAttention，ProxyAttn 是 training-free 方法、通篇没有蒸馏损失。

### 问题二：残差流的容量花在哪——表达力全押在读上，混合矩阵被扔掉

**论点：加宽与门控是互补的两笔账，本件的消融把收益精确归到「逐元素读」一处，写侧保持每支一个标量，支路间混合整个删掉。**

先隔离宽度本身。用一个适配 pre-norm（把归一化放在每个子层输入端、残差主干上不再加归一化层的结构）的简化 AltUp（Alternating Updates 的变体：$n_r$ 支残差流，每块持 $n_r$ 个可学习标量做加权读，块输出按深度轮转写回单支）：

$$
x^{(\ell)}=\sum_{i=1}^{n_r} h_i R_i^{(\ell)},\qquad
R_i^{(\ell+1)}=R_i^{(\ell)}+\mathbf{1}[i=\ell \bmod n_r]\, y^{(\ell)} .
$$

每块加 $n_r$ 个参数、零矩阵乘，额外代价只是携带多支状态的内存流量。25B-A3B 在 400B token 上降约 0.01 损失。宽度本身值钱，剩下的问题是在加宽的流上值得再叠多少读写机器。

Hyper-Connections（HC）一族把读写推广成三个算子：读算子 $H_{\text{mix}}$ 形成块输入、写算子 $H_{\text{combine}}$ 把块输出分发到各支、混合算子 $H_{\text{res}}$ 在支路之间交换信息；每个算子都是静态项加数据相关项。mHC（DeepSeek 的流形约束版本）把三个算子分别约束为 sigmoid、两倍 sigmoid、Sinkhorn-Knopp 投影到双随机矩阵（行列和均为 1 的矩阵流形，谱范数不超过 1、乘法闭合，迭代上限 20 次）。本件的 Gated Residual（GR）落点：

每支先独立归一化（group RMSNorm，每支一份增益 $\gamma_i\in\mathbb{R}^d$），读门从全部支路预测、逐支逐通道（$W_d\in\mathbb{R}^{d_{\text{low}}\times n_r d}$、$W_u\in\mathbb{R}^{n_r d\times d_{\text{low}}}$，瓶颈 $d_{\text{low}}=d/8=320$）：

$$
\hat{R}_i=\mathrm{RMSNorm}(R_i;\gamma_i),\qquad
G=\mathrm{unvec}\!\left(\sigma\!\left(W_u\,\mathrm{SiLU}\!\left(\tfrac{1}{n_r}W_d\,\mathrm{vec}(\hat{R})\right)\right)\right)\in\mathbb{R}^{n_r\times d},
$$

$$
x=\frac{1}{n_r}\sum_{i=1}^{n_r}G_i\odot\hat{R}_i ;
$$

写是每支一个数据相关标量，$W_w\in\mathbb{R}^{n_r\times n_r d}$ 是满形状，低秩瓶颈只在读侧：

$$
s=2\,\sigma\!\left(\tfrac{1}{n_r}W_w\,\mathrm{vec}(\hat{R})\right)\in\mathbb{R}^{n_r},\qquad
R_i'=R_i+s_i y .
$$

发布件对账：`hc_count=4` 对 $n_r=4$，`hc_lowrank=320` 对 $2560/8$，`output_gate_type=sigmoid`。读操作顶替块的 pre-normalization（块输入已经归一化并门控，加宽的流不再另设归一化层），静态项无增益、标准随机初始化够用。$H_{\text{res}}$ 删除后支路彼此独立：一支只被子层写、只经读操作被读。

消融链在 25B-A3B、560B token 上，九项基准与上面同一套管线（报告的 Table 5）：

|残差设计|损失|九项均值|
|---|---|---|
|pre-norm 基线|1.617|50.91|
|静态 mHC（$\lambda_\star=0$，只有宽度与静态读写）|1.596|52.49|
|动态 mHC（读写由状态预测）|1.594|54.47|
|GR（逐元素读门，无 $H_{\text{res}}$）|1.590|54.66|

被点名写出的分歧在静态到动态一步：损失只再降 0.002，平均精度涨 1.98 分（基线到静态涨 1.58 分）。作者把这处写进摘要级的总论点——损失单独看会低估这步改动的价值。五条消融观察定下 GR 的形状：sigmoid 门在损失与稳定性上都好过 tanh（与 mHC 的结论、与 GDN 和注意力组件里 sigmoid 好过 SiLU/tanh 的观察同向）；把读从每支一个标量细化到每支每通道有收益，把同样的细化搬到写侧几乎无收益，写保持每支标量；从全部支路预测算子好过只用最后一支或先池化，逐支归一化再加成；读写足够有表达力之后，$n_r\times n_r$ 混合算子带来不了显著提升。

与 mHC 的算子级对照是一处三行就能读完的账：mHC 的读映射 $\sigma(\cdot)$、写映射 $2\sigma(\cdot)$ 与 GR 的两个门同形，GR 把 mHC 的有界正门整套留下，把混合矩阵扔掉，同时把读粒度从每支标量移到每支逐通道。GR 对动态 mHC 的两项差（逐元素读门、去 $H_{\text{res}}$）换来双胜：损失 1.594→1.590，均值 54.47→54.66。删 $H_{\text{res}}$ 另收两笔效率与稳定性红利：每块省一次对完整残差状态的读（解码受内存流量支配，这是加宽流的主要推理成本），以及省掉一个需要单独约束的算子——报告明写约束件是潜在失稳源。

对照 Kimi 的 Attention Residuals（AttnRes：每层对先前各层输出做 softmax 注意力决定读，块版把层分成大小 $S$ 的块、每块求和成一个表示再对块做注意力）。本件在 28 层档复现（报告的 Table 6），$L$ 取 56 个子层（每层注意力块加 MLP 块），$S$ 数子层，粒度比 Kimi 原文的层级块细一档，两处的数字不同网格、不可并排引用：

|残差设计|损失|损失 + GatedNorm|
|---|---|---|
|pre-norm|1.789|1.787（−0.002）|
|Block AttnRes $S=4$|1.773|1.768（−0.005）|
|Block AttnRes $S=2$|1.770|1.766（−0.004）|
|Full AttnRes|1.762|1.758（−0.004）|
|GR（$n_r=4$）|—|1.762|

报告正文说 Full AttnRes 与 GR 持平于 1.762，比的是 Full AttnRes 的未加门值对 GR 的带门值（GR 的读里本来就含门，无门一栏是空）。两列都读时，28 层档 Full AttnRes 加门 1.758 领先 GR 的 1.762 约 0.004；48 层档 Block AttnRes $S=4$ 报 1.711、GR 报 1.707，GR 反超 0.004。加门对 AttnRes 各档降 0.004–0.005、对 pre-norm 基线只降 0.002，报告的读法是「子层读到的输入越复杂，门帮得越多」。

机制归因走支路分解。$H_{\text{res}}$ 删除后每支就是一个纯累加器，块 $u$ 对块 $v$ 输入的贡献可以精确算出：

$$
a_{u\to v}=\frac{1}{n_r}\sum_{c=1}^{n_r}G_c^{(v)}\odot\gamma_c\odot\frac{s_c^{(u)}y^{(u)}}{\mathrm{rms}(R_c^{(v)})},\qquad
\pi_{uv}=\frac{\lVert a_{u\to v}\rVert}{\sum_{u'<v}\lVert a_{u'\to v}\rVert},
$$

每个读者的份额之和与 1 的偏差在 $3\times10^{-8}$ 以内。对照件是 20 层 MoE 加 GR 对同配方同数据同优化器同步数的无 GR 参照，统计量取份额差 $\Delta_{uv}$（减掉参照是为了剥掉「近邻写者支配」这条所有残差网络共有的模式）。Figure 7 画 780 个有序对里 $\Delta_{uv}\ge0.05$ 且跳层至少 1 层的 21 条路径；标尺读数：第 15 层有 30 个写者、均分各约 0.03、份额 0.13 是均分的四倍。五个 GR checkpoint 各有一条长程支路，典型跳层 10.9，其余三支 3.4–3.9。三条样例：第 0 层 GDN 输出到第 15 层注意力的份额从 0.020 涨到 0.138，且在第 10 到 19 层的每个读者身上保持 0.072–0.138、无衰减趋势；第 10 层 GDN 到第 11 层注意力 $\Delta_{uv}=0.117$，单层跳同样强化——GR 同时加强短程；第 0 层 MLP 同时走长程（0.008→0.058）与局部（0.139→0.192）两条支路，同一份输出以不同强度到达近读者与远读者，单流网络每个写者只有一种衰减率、表达不出这种分层。按跳层分组求和：跳 1 层共涨 0.96，跳 12 层以上共涨 0.91，跳 2–12 层共跌 3.21；加权平均跳层 3.97 对 3.91，跨层信息总量近似守恒，变的是分布——GR 选中少数路径放大、资金来源是中程。读 GR 支路最重的子层集中在 softmax 注意力层，报告的读法：全局注意力是整合「被 GDN 压缩掉的显式长程历史」的枢纽。

推理侧两条试错各带一条教训。稀疏读写（每块只读门值最高的两支，训练从头稀疏或中途引入）在预训练损失与基准上几乎无损，后训练之后质量明显退化，改变稀疏度也不解决——报告把这处点名为「只看预训练指标会做错决定」的实例。FP8 存残差状态可行：GR、门控注意力、GDN 的门把写入幅度约束在窄区间，低精度格式正好匹配，字节数相对 BF16 减半、质量几乎不动。读写各融成单 kernel，group RMSNorm 折进读侧，加宽的流每块正反各遍历一次。同族方向上 xHC（小红书与上交的扩展件：写回侧多尺度因果卷积加稀疏支路更新，$N=16$ 支里每步只更新 $k=4$ 支）被点名，报告给的判断是更大的 $n_r$ 内存开销压过了稀疏更新的便利，未跟进。

### 问题三：嵌入侧容量买什么——两种预算下两本账，损失与下游分岔

**论点：n-gram 查表容量与 MoE 专家容量在扩容时扮演不同角色；这一说法立在两张消融表各自的读数形状上。**

机制：以每个 token 结尾的短 n-gram（本件取二阶与三阶）作键查嵌入表，查得的向量增强对应 token 的表示。参数量随词表规模涨、每 token 计算量几乎不动；寻址确定（键由输入直接算出，与内容无关），因此可以异步预取。发布件对账：`ngram_size=3`、`ngram_vocab_size_base=20000000`、`heads_per_ngram=8`、`ple_layer_ids=[2]`、`ple_embed_dim=2560`。模型卡的 51B n-gram 参数就此闭合：$20{,}000{,}000\times2560=51.2\times10^{9}$，8 个哈希头与阶数折进行空间（等价读法 160M 行乘 320 维，同一乘积）；20M 行对基线词表 250K 是 80 倍，发布件落在下面 Table 9 的 50V 与 100V 两行之间。报告与模型卡都没写这步换算，算出来即可核对。统一实验协议取 300 tokens per active parameter（TPP：tokens per active parameter，训练 token 数与激活参数数之比，本协议取 300）。

放置消融（报告的 Table 7；固定 n-gram 总参数，单层放置扫第 1/2/3/4/10/15/25 层，另测 2+15 与 2+25 双层）：无嵌入基线损失 1.585、九项均值 45.44；第 1 层 1.541/47.30，第 2 层 1.541/47.94，第 3 层 1.543/46.76，第 4 层 1.544/46.89，第 10 层 1.544/46.62，第 15 层 1.543/47.37，第 25 层 1.541/47.40；2+15 是 1.541/47.01，2+25 是 1.540/47.75。三处读数：第 1、2、25 层损失同为 1.541、下游均值差 0.64 分，损失一栏数字相同，放置的差别只出现在下游均值上；同一预算摊到多层没有一致收益；放置排序在 GDN 混合与全注意力下相似，选择与注意力机制基本无关。最终取第 2 层，理由落在工程侧：主机内存预取与第一层计算重叠。一处表格对账：两表的无嵌入档损失同为 1.585、第 2 层档与 50V 档损失同为 1.541；MMLU、MMLU-Pro、SuperGPQA、MATH、GSM8K、BBH、MMMLU 七列在 Table 7 的第 2 层行与 Table 9 的 50V 行逐列相同，说明放置消融跑在 50V 词表档上。两表末两列换了一对：Table 7 收 EvalPlus 与 MultiPL-E，Table 9 收 C-Eval 与 CMMLU。九项集合不同，两表的九项均值不可并排引用。

### 问题四：优化器与超参怎么闭环——分工、重拟合、压力测试三段

**论点：Muon 的收益要过三道工程关（权重分工、融合矩阵拆分、分布式等价），重拟合的缩放律把更激进的超参变成可检验的预测，稳定性余量在压力测试与生产 run 两级各自兑现。**

分工清单：Muon 只用在真正充当线性映射的二维权重上——注意力 q/k/v 与输出投影、GDN 输入与输出投影、路由专家与共享专家的两个前馈线性层 fc1/fc2（fc1 升到中间维、fc2 降回）、n-gram 的键值投影。输入嵌入、输出头、MoE 路由、GR 的两个低秩投影、注意力与 GDN 的输出门走 AdamW；n-gram 表本体走关掉权重衰减的 Adam。报告逐条给理由：路由上 Muon 放大早期训练波动，中后期再上不致失稳也无明显收益，作者自己把解释写成猜想（路由每个输出维对应一个专家的分数、维度间基本独立，没有共享线性结构给正交化利用）；GR 的两个低秩投影因形状过长走 AdamW 更好；输出门上 AdamW 与 Muon 持平或略好；GDN 的衰减与 beta 投影每头出一个标量、是向量，正交化无意义。这条分工在公开文献里两侧都有位置：Moonshot 在《Muon is Scalable for LLM Training》里把 Muon 用在包括路由在内的矩阵参数上，并报告 Muon 带来的 SVD 熵提升在路由权重上更显著；《Symmetry-Compatible Principle for Optimizer Design: Embeddings, LM Heads, SwiGLU MLPs, and MoE Routers》（arXiv 2605.18106，报告未引，外部对照件）从对称性一侧论证双随机正交更新与路由的置换对称不相容、建议路由离开谱类更新。本件的观察与该文口径同向，报告以「One possible explanation」自标猜想身份。

正交化配置：Newton–Schulz 迭代跑在 Nesterov 加速动量（$\mu=0.95$）上，正交化结果按形状缩放

$$
\gamma(A,B)=0.2\sqrt{\max(A,B)}
$$

使更新 RMS 与矩阵形状无关。回 PDF 版面核对：根号存在（抽取文本把 √ 丢成行首孤立的 `p`；摘要页的同一处已按这一版面订正为 $0.2\sqrt{\max(A,B)}$，两页口径一致）。这一缩放式的出处是 Moonshot《Muon is Scalable for LLM Training》的式 (4)，动机是把 Muon 更新的 RMS 配到 AdamW 常见的 0.2–0.4 区间；Nesterov 动量则是 Muon 原始实现的默认。迭代步数取 8、系数用 Polar Express 的逐步表（该表解给定步数预算下的极小极大问题，其主实验用 5 步、消融按损失判优到 6 步封顶）；本件把 8 步的理由落在稳定性一侧——压力测试里梯度范数尖峰的幅度与频次都降——与 Polar Express 按损失判优的口径不同档。Frobenius 归一的数值稳定常数取 $10^{-14}$。

融合矩阵按语义拆开再喂 Muon：Megatron 框架把注意力 qkv、SwiGLU 的 fc1、GDN 输入投影各存成一个融合矩阵，语义上它们是沿输出维拼接的独立线性算子，对融合矩阵做正交化会把无关子块的奇异方向搅在一起、缩放式也会按拼接后的假形状算。qkv 与 GDN 输入投影按头拆，损失与下游同升；fc1 拆成 gate 与 up 两半，损失基本不动、下游略升。拆分顺带给出把单个子矩阵排除在 Muon 之外的粒度。

分布式实现自研 Canzona（同组另一篇独立论文，作者表与本件重合）：Newton–Schulz 要求对每个完整参数矩阵做整体更新，$K$ 步约 $4K\max(A,B)\min(A,B)^2$ FLOPs，与 Megatron 的分片冲突两处——张量并行下没有 rank 持有完整权重，数据并行下代价随短边立方、等元素切分留下严重掉队者。Canzona 把逻辑优化器分配与物理参数布局解耦：静态分区器搬运整参数（张量内不切）把各数据并行 rank 的估计迭代 FLOPs 拉平，异步 Micro-Group 流水线用融合 All-to-All 跨张量并行重建每个 Muon 所属矩阵，owner 跑的步与单设备 Muon 数学等价，ZeRO-1 的桶几何保留、梯度归约与反向的重叠不丢；报 1.7B–32B 档 256 卡端到端迭代 1.57 倍加速、优化器步延迟降到约五分之一。拆完之后一层贡献上百个子矩阵，优化器步成为一长串受 kernel 启动开销约束的小算子，整步用 CUDA graph 捕获。

## 我的分析

本节全部是精读判断，标注与分析对象分开。

### 判定一：两种预算的分岔——容量类型决定收益去向，Table 8 自身混着两件事

增强页给了三条候选解释，我按数字裁定。

分岔的主因落在容量类型上（候选解释一成立，判据在本篇问题三的三处数字）。固定总参数档，n-gram 换的是专家：域内损失最多换回 0.005，域外困惑度全程 5.54–5.59，九项下游零一致改善——换容量的净收益被削专家的损失吃掉，且吃得很干净。固定 MoE 档，n-gram 是纯增容量：损失单调降 0.059（约为前档最大收益的 12 倍），下游收益集中砸在词表敏感项——中文两项 +8.03 与 +5.14 全程单调，MMLU 缓涨；计算敏感项 MATH、GSM8K、BBH 早早见顶。两档并读，形状自洽：静态查表买到的是局部共现与词形覆盖这类可预测内容（中文分词与形态恰是词表敏感项），推理与数学要的计算侧容量在专家与注意力里，表买不到。报告自己那句「n-gram 嵌入与 MoE 专家在扩容上扮演不同角色」是这一判断的保守表述，数字给的版本更强：两种容量在损失上可以互换、在能力上不能互换。

候选解释二（Table 8 里削专家同时改变路由粒度，读数混着两件事）成立，且报告的设计选择本身就是证据——作者放弃固定总参数档转用固定 MoE 档重测，等于承认前档把两个变量捆在一起。这一条读作对 Table 8 的解释限定，动摇不了分岔形状本身。

候选解释三（MATH/GSM8K 在 20V 见顶后回落是「表够覆盖局部共现、再扩只稀释专家」）证据不足，维持悬置。回落幅度（MATH 37.38→35.34、GSM8K 65.09→62.96）与单次评估的噪声同量级，Table 9 没有给任何方差信息；20V 一档相对无嵌入的涨幅（MATH +4.86、GSM8K +5.88）远大于其后的回落（2.04 与 2.13），回落与涨幅之比约 1:2.4 与 1:2.8。判这条需要更长预算或分任务类型的损失分解，报告两者都没做。

一个补充读数：固定总参数档里唯一一致的下游信号是 C-Eval 在 30×（50%）处跳到 72.49（基线 70.78），同档 MMMLU 恰在最低（56.22 在 10×，30× 处 56.66）。中文收益与多语损失在削专家最狠的档位同现，与「表帮词形、专家帮跨语计算」的分工图景相容。

### 判定二：GR 回到受约束混合的可能性——当前设计点证据充分，判「不回头」；外推只在更大宽度处开口

增强页的猜想是「GR 去掉 $H_{\text{res}}$ 之后，后续件可能回到受约束的混合」。我驳回它作为对本设计线的预测，保留它作为对宽度外推的开放问题，判据四条。

其一，消融把混合矩阵的价值测没了：读写足够有表达力之后 $n_r\times n_r$ 混合「带来不了显著提升」，GR 对动态 mHC 在损失与均值上双胜（1.590/54.66 对 1.594/54.47），mHC 的混合矩阵正是被约束保护的对象——约束件自己的功能已被更细的读粒度替代。其二，删它换来三笔正收益：每块省一次完整残差状态读（解码受内存流量支配，这是加宽流的主要推理成本）、省掉一套约束机器（Sinkhorn-Knopp 投影连同其「潜在失稳源」标签）、支路彼此独立让信息流可精确分解归因。三轴协议下没有任何一轴为它说话。其三，支路分解显示 $n_r=4$ 时分工自发涌现：五个 checkpoint 各有一条长程支路加三条局部支路，无混合下网络自己学会了「一支保早层、三支走近邻」——混合矩阵要解决的问题（支路趋同、容量闲置）在这个宽度上没有出现。其四，报告的轨迹方向是去约束：静态项删了（mHC/HC 保留、GR 不要）、特殊初始化删了（标准随机初始化够用）、混合删了，稳定性叙事全部押在有界门上。

开口留在宽度上。xHC 的稀疏支路更新走的是大 $n_r$ 路线（16 支更新 4 支），报告点名后以内存开销为由不跟进。支路一多、每步写者一稀疏，「支路饿死」这类混合矩阵原本要防的模式才可能出现。当前配方 $n_r=4$ 稠密读写离那个区间很远。我的判断：这条猜想在 Qwen 这条线上被后续件证实的先验低；若哪天回归，回归的形态更可能是大宽度加稀疏更新（xHC 的问题域），回到 mHC 式双随机约束的概率排在它后面。

### 判定三：ple_* 与 ngram_* 双键名——概念双源成立，实现谱系证据不足，降级为设计注脚

发布件 config 同时带 `ple_layer_ids`/`ple_embed_dim`/`ple_conv_kernel_size` 与 `ngram_size`/`ngram_vocab_size_base`/`heads_per_ngram`/`split_ngram_parts` 两套键名，增强页猜这是「实现谱系同时接 Gemma 3n 与 Engram 两条线」的痕迹。我的判定：两套键名记录的是两个正交的设计决定，双命名是这套设计的自然写法，够不上代码谱系证据。

拆开看，`ple_*` 一族回答「表放哪、多大维、查完怎么加工」——层位（第 2 层）、嵌入维（2560）、查得向量上的短卷积核（4）；`ngram_*` 一族回答「键怎么构造」——阶数（3）、基表行数（20M）、哈希头数（8）、分片与对齐粒度。放置概念出自 per-layer embeddings 一支（Gemma 3n 把 PLE 表缓存在本地快速存储、E2B（有效参数量 2B 档，实际有效加载约 1.91B 参数），Gemma 4 报告沿用此件），寻址概念出自 n-gram 哈希表一支（Engram 的后缀 n-gram 多头哈希、素数表大小、$O(1)$ 查表、CPU 卸载运行时预取）。报告 §2.3 的动机段本来就把两条线并排引。任何同时做这两个决定的实现，无论抄没抄代码，都需要两套词汇。

三条硬证据缺口把「实现谱系」的强读法压回弱读法。Engram 一侧：其发布件在本次核对时点没有可公开的权重仓库，官方代码仓库 README 里没有 n-gram 配置键样例，键名无从比对。Gemma 3n 一侧：谷歌的内部实现键名不可考，公开概览页只给概念。中间人 `ple_conv_kernel_size=4`：查得向量过一个长度为 4 的短卷积再并入表示——这一步在报告 §2.3 正文里一个字没提，属于只在发布件里现形的实现细节；X-GRAM 一支用归一化 SwiGLU ShortConv 精修查得向量，键名暗示本件也做了同类精修。这条细节支持「实现吸收了嵌入扩容一族的经验」，同样到不了「接了某家代码」。

结论：双键名是概念双源的好注脚、是报告引用谱系的发布件回声，作为实现谱系证据判不足。顺带一条可跟踪的账：`ple_conv_kernel_size` 指向的查表精修件是报告正文与发布件之间目前唯一已知的「config 有、报告正文无」的架构信息差。

### 横向：与 Kimi K3 的三处同题异构

本件与本库已入库的 Kimi K3 一脉在三个相同的问题上给出相反或不同的答案，值得并排记账。

位置编码的取舍正面相撞。K3 的多头潜在注意力（MLA）层全部走 NoPE，理由是 Kimi Delta Attention（KDA）的 delta 项与广义旋转位置编码存在等价关系（博客作者给的 PaTH 改写，PaTH 是 Householder 变换位置编码，该改写给查询与键各减一个 DeltaNet 项，可等价写成带正交幂旋转的形式，delta 层因此自带位置信息），加回 RoPE 效果看不出变化、按简洁原则删掉。本件的观察在预训练阶段与 K3 完全同型——RoPE 与 NoPE 损失看不出差别——分歧出在评估轴：本件量到 NoPE 变体后训练 endless generation 率明显升高，于是保留 RoPE。两件都是混合架构（GDN 加全注意力对 KDA 加 Gated MLA），循环侧一个用每头标量衰减、一个用逐通道衰减门，全注意力侧一个保 RoPE 一个走 NoPE。这条对质没有输家，它把「位置编码可省」从一个二值判断拆成了三个变量：循环件的门控粒度、评估截到哪一段、后训练对终止行为的敏感度。K3 一侧的账只量到预训练与基准，本件一侧量到了后训练终止率，两家的证据覆盖面不同。

残差加宽的粒度选择分岔。K3 取 Attention Residuals 的块版，8 块乘 12 层、块按层计；本件 Table 6 的复现把块按子层计（28 层折 56 个子层），本件 GR 干脆不做层级注意力、走 4 支加宽流加逐元素读门。K3 的块注意力读全部前序块表示、每层一个学习伪查询；本件的读门从当前残差状态预测、每支每通道一个权重。两家的数字网格不同（层级对子层级），本篇问题二已标注不可并排引用；能并排的是判断：两家都认定「每层读什么」值得学、都拒绝让所有层等权累加。

稀疏注意力的索引成本归处。K3 的 Gated MLA 走压缩缓存路线（每 token 的键值压成低维潜变量），省的是缓存字节；本件 QSA 走检索路线（每查询只算 2048 个 token 的注意力），省的是计算量。DeepSeek-V4.1-Flash 与本件同代，两家都把 DSA 的 token 级索引器动了一刀：本件降到块级加 4 头；DeepSeek-V4.1-Flash 让索引器键由主 KV 投影而来，并把主 KV、索引器键与 Top-K 索引沿层复用，后层只在首个全注意力层建起的候选池内重打分（候选池 2048 块、每块 8 个位置）。索引器自身的 $O(n^2/r)$ 仍随长度平方增长，只是常数被 $r$ 压住——这条路线的天花板（索引器自己成为瓶颈）报告在 Figure 6 的读数里已经露头：1M 处索引器延迟占注意力模块的相当份额。

### 通读判断：这是一篇评估协议论文，穿着模型报告的衣

把 28 页读完，四处架构改动的每一处都有具名前作（DSA、HC/mHC/AltUp、Engram/Gemma 3n、Muon/Moonshot），本件在架构空间的净增量是粒度选择（块级打分、逐通道读门、第 2 层放置、按语义拆融合矩阵）。真正的新东西在评估侧：三轴协议被当成方法论写进报告的摘要、§1、§5 三处，报告全文的叙事单元是「一条主张在三轴上的读数形状」，而被协议拦下的三条捷径（稀疏写后训练退化、位置编码后训练现形、批量 warmup 白花步数）是这套协议交出的答卷。作者给下一步定的瓶颈也在评估：「一个能可靠预测后训练排序的更便宜中规模探针会让设计空间更好搜」。这份报告的可复用产出，对做架构的人是那几张消融表的数字，对做流程的人是那套协议——后者的迁移半径大得多。

预览件体裁配合了这个判断：权重先于报告两天挂出（Hugging Face 仓库 2026-08-24 创建，报告 PDF 元数据 2026-08-26），报告先于 arXiv 挂出（2026-08-31），架构类名直接印着 `Qwen4Exp`。官方把一份「Qwen4 的架构草稿」交给社区检验，检验工具就是报告自己申明的那三轴。本篇按 PDF 版面采用 $0.2\sqrt{\max(A,B)}$，摘要页同一处也已回改；预览件的体裁里发布件跑在前面、核对工作跟在后面，这类式子与命名的订正正是它该有的遭遇。

Muon 分工那条再补一笔外部位置：本件把路由留在 AdamW 并自标猜想，Moonshot 把路由放进 Muon 并报告其 SVD 熵提升在路由上更显著，《Symmetry-Compatible Principle for Optimizer Design》（arXiv 2605.18106）论证路由与谱更新不相容。三件并排，本件的实践读数与理论口径同向、与先行实践口径相反，报告没有调和这一处。这是留给后续件的一条开放账。

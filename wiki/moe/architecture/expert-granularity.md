# 细颗粒度专家

细颗粒度专家出自 DeepSeekMoE（arXiv:2401.06066），做法是让每个专家更小、数量更多。Expert 是 MoE 层里切出来的窄 MLP，一个 token 只走 Router 挑出的 k 个，Router 是预测每个专家模长的小模型。[[moe-layer|MoE 层：把 MLP 换成并行专家]]

## 规则改动与组合数

把每个专家缩小一半、总数从 n 增到 2n，挑选规则从 n 选 k 改成 2n 选 2k。总参数与激活参数都不变：每个专家小一半，激活的专家数多一倍，两者相乘回到原来的量。

可选组合数由此增长。原规则下的组合数是 C(n,k)，它表示从 n 个专家里挑 k 个有多少种搭配；改动后是 C(2n,2k)，后者远大于前者。激活的参数总量保持在同一档，可选搭配的种类多出许多。第五篇把这条组合数的增长列为细颗粒度更优的一项形式化说明。

## 细颗粒度更贴合非均匀分布

现实世界里的知识分布不均匀，不同任务与概念的密度在空间里高低起伏，一大一小两团并存的形状很常见。更多的、更细的专家能把这种非均匀性覆盖得更贴合。第五篇用这张图说明：

![[raw/2025-05/moe/spaces-ac-cn/moe-huanyouji-5/assets/moe-huanyouji-5-fig1.png]]

图：左侧是知识的一大一小两团分布，右上用两个总面积相同的大圆覆盖，右下改用八个总面积相同的小圆覆盖，小圆的贴合更细。图取自《MoE环游记：5、均匀分布的反思》。这一节的原始论述见 [[moe-huanyouji-5-abstract|MoE环游记：5、均匀分布的反思 摘要]]。

图里两侧的参数预算相同，两个大圆与八个小圆的总面积相等，差别落在覆盖的贴合度上：大圆把大团之外的空处一并圈了进去，小圆能贴着两团的实际边界铺开。这一侧小圆的数量变多、半径变小，正对应专家总数翻倍、单个专家缩小一半这条规则改动。

## 与共享专家并列的第二件改进

DeepSeekMoE 给出的两件改进在系列第五篇里并置：共享专家改变哪些专家必然入选，细颗粒度改变专家的尺寸与数量。两件改进都保持总参数与激活参数不变，改动落在算力怎么用上，这也是两页放在同一层目录里的原因。[[shared-expert|共享专家与比例因子]]

## 代价与舒适区间

专家数 n 越大，负载越不均衡，通信与协调成本上升。负载不均衡指的是各专家分到的算力与实际收到的 token 数对不上，专家越多，这份偏差越难压下去。[[load-balancing-problem|负载不均衡的两类浪费]]

覆盖能力与这两项代价一起随颗粒度变化，这条路线因此存在一个效果与效率都友好的舒适区间，颗粒度的选择落在这个区间里。第五篇把这项代价与共享专家的代价并列记在一起，两件改进都让这一层更不均匀。

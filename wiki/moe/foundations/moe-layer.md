# MoE 层：把 MLP 换成并行专家

MoE（Mixture of Experts，混合专家）把一个 Transformer 里的 MLP 层换成若干并行的小网络，每个 token 只走其中几个。MLP 是 Transformer 里的全连接前馈层，由两个参数矩阵夹一个逐元素激活函数构成。token 是模型处理文本的最小单位，通常是一小段词或子词，也是这一系列文章计量的单位：参数量按专家计、计算量按激活的专家计。

## MLP 分块后就是若干小网络之和

常规 MLP 层写成 `y = f(xW^(A))W^(B)`。这里 `x` 是输入行向量，`W^(A)` 与 `W^(B)` 是两个参数矩阵，`f` 是逐元素激活函数，对每个分量独立作用。

设这一层的中间宽度为 D。把参数矩阵按列与行分块之后，这一层的输出等于 n 个小网络输出之和，其中每个小网络的中间宽度 c 等于 D / n。每个小网络就是一个 Expert，它是这一层被切出来的窄 MLP，仍然由两个较小的参数矩阵构成。

MoE 要回答的问题由此写成：能否只挑其中 k 个小网络求和，用它们逼近原来 n 个之和，把这一层的计算量降到 k / n。这一节的原始论述见 [[moe-huanyouji-1-abstract|MoE环游记：1、从几何意义出发 摘要]]。

## 参数量与计算量解耦

这一换法带来两条各自增长的量：

- 参数量随专家总数 n 增长，全部专家的权重都留在显存里；
- 计算量随实际激活的专家数 k 增长，一个 token 只走被选中的那几个。

两个量因此解耦：加专家可以加容量，每个 token 的算力开销保持在 k 个专家一档。这也是 MoE 被采用的理由，它把「模型多大」与「一次算多少」拆成两件独立可调的事。

## Router 是谁

挑那 k 个专家的活由一个小模型承担。它做一次从 d 维到 n 维的线性变换，末尾接一个非负激活函数，输出每个专家的一个分数，这个小模型就是 Router。d 是输入向量的维度，n 是专家总数，所以 Router 的输出长度与专家一一对应。

Router 的产物最初被解释为每个专家的模长，也就是该专家输出向量的长度。把模长与方向分开重新参数化之后，挑选与计算可以按固定顺序做完，整个 MoE 层的输出写成基线形式 `y = Σ_{i∈argtop_k ρ} ρ_i e_i`，其中 ρ_i 是 Router 给第 i 个专家预测的模长，e_i 是该专家输出向量的归一化方向。[[router-magnitude-direction|Router 的方向-模长重参数化]]

## 挑法依赖的假设

最优挑法是保留模长最大的 k 个，这条结论建立在一项假设上：各 Expert 的输出向量两两正交。正交指两个向量的内积为零，夹角 90 度。在这个近似下，被丢弃向量的模长平方之和就是逼近误差。[[expert-orthogonality|Expert 正交假设]]

## 训练时先分算力再路由

MoE 训练时先按专家分配算力，再把 token 路由过去。这个顺序决定了负载均衡问题的形状：某个专家分到的算力与它实际收到的 token 数对不上时，多出来的那部分算力被浪费在等待上。[[load-balancing-problem|负载不均衡的两类浪费]]

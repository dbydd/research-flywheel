# MoonEP：全均衡专家并行

专家并行把一层里的专家分散到不同设备上，每个设备承担其中一部分。常规做法下 token 在这些设备之间的负载不均衡，计算量最大的设备拖慢整条流水线；路由专家按 token 动态激活，激活形状随之变化，显存里留下大量碎片。MoonEP 出自《Kimi K3》技术报告，用动态冗余专家做到完全均衡，是 [[trillion-scale-parallelism|三万亿级预训练并行]] 里专家并行一侧的第一个难题解。

## 指派分配与均衡条件

每个 rank 持有一段长度为 S 的序列，S 是每个 rank 本地的序列长度。段内每个 token 选出 K 个专家，这个 rank 因此有 S×K 份「token 交给某个专家」的指派，发往各个 rank（rank 是并行训练里的一个设备进程）。完全均衡要求每个 rank 恰好收到 S×K 份指派，其中包含它自己发出去的那一份，所有 rank 的计算量因此相等。

均衡方案总存在。报告证明每个 rank 至多使用 E/R 个冗余专家，E 是专家总数，R 是专家并行度；最坏情形需要 $\lceil E(R-1)/R^2\rceil$ 个，R 大时这个值接近 E/R，上界因此基本紧。每个 rank 预留 E/R 个冗余专家槽位，规划在任何输入分布下都可行，训练不会因为找不到均衡方案而停下。先行工作预置固定的冗余专家数，或者对单个 rank 的 token 数施加上限，可行方案不存在时训练只能中断。

## 规划

规划问题用整数线性规划离线求代表情形的精确解，作为参照。在线部分由一个 GPU 规划内核求解：它近似最优，开销可忽略，并且始终守住 E/R 这个上界。

## 通信缓冲

完全均衡让通信路径也变短。融合的 permute 与 unpermute 算子由规划内核预先算好每个 token 的去向，token 直接发到远端 rank 上按专家分组的位置，通信缓冲的视图直接交给计算，中间拷贝省掉。最坏不均衡下 DeepEP 需要 $S\times K\times R$ 的通信缓冲，MoonEP 的缓冲固定在 $S\times K$。

## 静态形状

完全均衡使各层的计算形状静态可知，逐层的 MoE 主机同步被消掉，主机侧的内核启动开销随之缓解。

## 单 rank 内的偏斜

单个 rank 内各专家的 token 数仍有偏斜。工作负载感知的调度器在启动前按当前 token 分布调整参数，执行期间保持这些参数；参数由一个启发式选取，它用硬件指标上的解析代价模型，并经过离线自调标定。共享专家的 GEMM 派到单独的流上，与其它内核重叠。[[latent-moe|潜空间专家]] 用共享专家保留全宽路径，这里的共享专家计算沿用同一条组织。[[load-balancing-problem|负载不均衡的两类浪费]] 记的两类浪费落在设备之间与设备之内两层，MoonEP 从跨 rank 的均衡与单 rank 内的调度两侧分别处理。
